## 使用方式

生产入口保持：

```powershell
out/build/windows-msvc-debug/Editor/JanusEditor.exe --project SandboxProject --mcp-stdio
```

新增工具：`runtime.play`、`runtime.pause`、`runtime.stop`、`runtime.step`、`transaction.begin`、`transaction.commit`、`transaction.rollback`。现有六个 Scene mutation 和 Save 保留。

事务示例（这里展示工具名与 arguments；外层继续遵循现有 MCP 协议）：

```json
{"name":"transaction.begin","arguments":{"label":"Create agent entity"}}
{"name":"scene.create_entity","arguments":{"name":"AgentEntity","transaction":"<begin 返回的 UUID>"}}
{"name":"transaction.commit","arguments":{"transaction":"<同一 UUID>"}}
```

成功创建工具返回实体 UUID 和 command receipt。Commit 后一次 Human Undo 撤销整个组；Commit 不保存磁盘。活跃事务中的 Scene read 带 `authoringTransaction.provisional=true`。读取令牌不授予写入权，host 还检查真实连接所有者。

```json
{"name":"runtime.play","arguments":{"startPaused":true}}
{"name":"runtime.step","arguments":{}}
{"name":"runtime.stop","arguments":{}}
```

`startPaused` 只在 Stopped 接受；已有运行实例请用无参数 Play 恢复。Step 使用空输入和 1/60 秒，不进行热重载；每次新 Play 刷新所需 Lua 源码，保证 Stop 后的磁盘修改生效。

| 资源 | 查询参数 / 行为 |
|---|---|
| `engine://runtime/status` | 四态、runtimeId、成功帧号、失败帧和错误 |
| `engine://runtime/entity/{uuid}` | 运行态 Reflection 属性；Stop 后读取失败 |
| `engine://logs/recent` | after、limit 1–200、level Info/Warning/Error、category、runtimeId |
| `engine://profiler/latest-frame` | 无参数为最近完成帧；frameId 查询保留历史；缺失返回 available=false |
| `engine://transaction/status` | Active / Idle / RecoveryRequired、临时状态及额度 |
| `engine://agent/activity` | after、limit 1–200、transactionId 筛选 |

日志和 Activity 的 sequence 为查询游标；保留区间之外返回 gap。UUID、命令 ID、Reflection ID 用字符串编码；CPU scope parent 是当前帧数组索引。资源页按最终 stdio 嵌套 JSON 的大小预算截断，不保证一次返回所有请求条数。

## 实现决策和边界

- Runtime 是 Engine 类型，旧 Editor header 保留兼容 alias。MCP 通过主线程 host 注入能力，不引用 EditorActions / ImGui。作者态所有常规写入口共享 ProjectSession guard。
- Application 持有共享 LogStore 并通过 spdlog sink 接收 Core/客户端日志。ProjectSession 注入该存储；GPU-free fixture 自有存储。Profiler 和组合帧由 ProjectSession 显式持有，Core recorder 与 Scene/Renderer 解耦。
- 分组和有界 Activity 存储直接封装在 Core CommandBus 内，避免再引入一个独立 Manager；CommandReceipt/effects 由实际 Engine command 产生。诊断 observer 禁止重入，诊断失败不改变命令业务结果。
- Activity 最多 2,000 条；描述/错误各限 1 KiB、最多 16 个 effect 摘要，保留总数和 truncated。它不持久化，不是认证或防篡改审计。原始参数/源码不存储；非命令操作记名称和结果。
- 事务上限 64 个命令、60 秒、8 MiB 预留撤销数据，终态缓存最近 32 个。反射/删除命令以全 Scene 的保守估算覆盖 Camera.primary 连带修改和子树恢复；大 Scene 的小修改可能较早触及额度。这里是保守 reservation，不宣称精确 heap 计量。
- 事务为可见临时执行；没有数据库隔离、磁盘原子提交或 Runtime 帧回滚。失败恢复不了时冻结写入、Save、Play，Human 通过 Activity 面板明确放弃未保存内容并从磁盘恢复。恢复后 MCP 按 scene revision 刷新绑定。
- Profiler 保留最多 120 帧、每帧最多 4,096 scope；UI 与 MCP 使用同一完成帧快照。资源序列化有额外大小上限，遗漏用 omittedScopes 表示。CPU duration 为包含子 scope 的 wall-clock 区间，不能相加当作总 CPU，更不是 GPU 时长。
- 隐藏/失败的渲染 pass 为 unavailable；统计在该 pass 完成后、下一次 Renderer reset 前复制。实体数与 sprite/draw 数分开。
- 不增加依赖。生产版本由 CMake `PROJECT_VERSION=0.9.0` 传给 MCP server info。

### 真实 Editor 和 MCP 客户端

使用原生 JanusEditor / OpenGL、临时 SandboxProject 副本，以及本地 Node JSON-RPC smoke client（本次 v0.9 脚本，主协议 `2026-07-28`）建立真实 stdio 连接。

- MCP 创建并提交 Agent 事务；在真实工具栏点击一次 Undo，实体消失，Activity 出现 `Human / Undone` 且保留原 commandId。
- startPaused 后真实 UI 显示 Stop / Resume / Step；点击 Step 后运行帧从 0 到 1，仍为 Paused。
- 修改临时 Lua 令 OnUpdate 报错，再 Play/Step 后为 Faulted、failedFrameIndex=1、成功 frameIndex=0，场景仍可显示。
- Console 与 `logs/recent` 都出现同一条 Lua 故障（含实体 UUID 和脚本 UUID），未重复记录。
- Scene pass：4 entities、2 sprites、2 draw calls；切换 Game 后 Game pass 同样为 4/2/2、Scene pass 为 null。Profiler 标签布局经截图复查，没有覆盖编辑视图。
- 结束测试时通过 Editor Escape 正常退出，未保存临时作者态修改。现代和 legacy 子进程 E2E 另行验证生产 handlers、事务错误、EOF 回滚及 stdout purity。

未验证第三方 Agent 客户端的特定 UI/版本，也没有据此宣称跨平台或 GPU 性能保证。
