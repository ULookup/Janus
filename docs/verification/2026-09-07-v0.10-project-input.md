## 交付

| 能力 | 实现与验证入口 |

| 两个运行入口 | managed Application 和 RuntimeSession 都使用同一 ProjectSettings/InputBindings；Paused Step 保持中性输入 |
| Editor 制作入口 | Project Settings 标签，可编辑路径、显示设置、增加/删除 Action 和编辑多个绑定；独立表单滚动，标签栏保持可访问 |
| Game View 路由 | 使用项目宽高比、逻辑指针坐标；面板/黑边/隐藏视图/文本编辑不输入 Gameplay；离开视图释放一次 held 状态 |

## 项目配置

`project.json` 位于项目根目录。`version` 必填，当前为 1；其余字段缺省时使用下方默认值。未知字段、重复字段、错误类型、未知按键或重复绑定均明确报错。最大文件 64 KiB。

```json
{
  "version": 1,
  "name": "Janus Project",
  "defaultScene": "Scenes/Battle.scene",
  "assetRegistry": "Config/AssetRegistry.json",
  "assetRoot": "Assets",
  "scriptRoot": "Scripts",
  "width": 1280,
  "height": 720,
  "vsync": true,
  "targetFps": 0,
  "inputBindings": {
    "MoveLeft": ["A", "ArrowLeft"],
    "Confirm": ["Space", "Enter"]
  }
}
```

上例的 bindings 是示范；省略 inputBindings 时为空，Engine 不生成游戏动作名。名称最多 128 UTF-8 字节；动作名为 1–64 个 ASCII 字母、数字、下划线、点或连字符。分辨率每轴 1–16384；Target FPS 为 0–1000，0 表示不主动限帧。VSync 与 CPU 帧率上限同时生效；设置 swap interval 失败时记录警告，不关闭主动限帧。

路径必须是项目相对路径，拒绝根路径、越界、ADS 等非法形式，并检查磁盘解析后是否仍在项目根内。显式 `ProjectRuntimeConfig::assetRegistryPath/startupScenePath` 覆盖 manifest；未指定则使用 manifest/default。配置失败不会悄悄加载另一份 Scene。

| 设置 | 生效时机 |
|---|---|
| Input bindings | 保存后的下一次 Play；当前 ScriptEngine 持有独立快照 |
| Default Scene / Asset registry | 下次打开项目；不会丢弃当前未保存 Scene |
| Asset root / Script root | 持久化内容目录声明；本切片无导入器，不移动文件、不改写现有资源引用 |
| 游戏分辨率 | Editor Game View 保存后使用新宽高比；独立游戏下次启动使用新窗口大小 |
| VSync / Target FPS | 下次启动 Editor 或独立游戏 |

设置保存不是 Scene Command，不进入 Undo/Redo；设置面板的 Revert 只恢复未保存表单。运行态和事务保护在 ProjectSession 生效，不能靠禁用按钮替代。

## Lua 与输入语义

```lua
if Input.has_action("MoveLeft") and Input.is_action_down("MoveLeft") then
    local x, y = self.entity:get_position()
    self.entity:set_position(x - 180 * dt, y)
end

local pressed = Input.was_action_pressed("Confirm")
local released = Input.was_action_released("Confirm")
local x, y = Input.pointer_position() -- 无有效指针时返回 nil
local clicked = Input.was_pointer_button_pressed("Left")
```

还提供 `is_pointer_button_down`、`was_pointer_button_released`，按钮名为 Left/Right/Middle。未知 Action/按钮在 Lua 中形成受控错误；C++ Action 查询返回空 optional。原 `is_key_down/was_key_pressed/was_key_released` 保留。

Action down 为绑定键 OR；pressed/released 按帧边界聚合。另一键仍按住时不报告释放；一帧内短按保留 pressed 和 released；已按住 Action 在同帧释放后再按回，不制造新的边界转换。OS repeat 不制造 pressed，失焦清除未消费的 pressed 并释放 held。键盘与指针边缘状态每帧清空。

Game View 以鼠标位于实际游戏画面且没有文本输入焦点作为输入条件。逻辑坐标为项目分辨率，原点左上，向右/下为正。工具面板和 letterbox 不驱动游戏；后续 Game UI 内部的事件消费/世界路由将在 UI 切片实现。

## 真实 Editor 与 MCP 读回

使用本次构建的原生 JanusEditor/OpenGL、临时 SandboxProject 副本和本地 JSON-RPC client。UI 操作通过 Computer Use；未编辑用户已有项目。

- 在 Project Settings 中将 MoveLeft 第一绑定从 A 改为 W，保存后直接核对临时 `project.json`，结果为 `["W", "ArrowLeft"]`。
- 关闭并重新打开该项目，点击 Human Play；临时 Lua 用 `was_action_pressed` 将一次动作转成 x -= 10，避免短暂合成按键在帧间不可观察。
- 鼠标在 Game View 内按 W，MCP 读取 Runtime Player.x 从 -80 变为 -90；按旧 A 保持 -90。
- 鼠标移到设置面板后按 W，Runtime x 保持 -90；运行中设置面板和保存按钮禁用，底层拒绝由自动测试验证。
- 临时 Lua 通过 `pointer_position` 输出有效的逻辑坐标，确认 Game View 路由到 Lua。映射数值和边界由单元测试验证。
- 修正了长表单卷走 Utility 标签栏的问题；复查独立滚动后标签栏仍显示，保存按钮可到达。
- Stop 后通过作者态 entity resource 读回 Player.x = -80，运行修改未污染 EditorScene。随后正常关闭 Editor。

临时项目和结果保留在 ignored `out/v010-live-PBP3dN/`。自动化 `Left` 注入实际产生 SDL scan 92（KP_4），而方向键 Left 是 scan 80；通过临时原生日志定位后已移除诊断代码。因此真实按键验收采用 W，ArrowLeft 的绑定与运行行为由集成测试覆盖，不宣称已验证物理方向键或小键盘映射。
