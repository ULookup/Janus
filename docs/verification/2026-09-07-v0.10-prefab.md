## 交付

- `janus.prefab` v1 单根子树资产，1 MiB / 1024 实体 / 64 层限制；严格结构、重复键、
  未知字段、嵌套模板、断链/循环、多根、兄弟序号、UTF-8 和 JSON 深度校验。
- active ReflectionRegistry + Scene v1 编解码，复用删除命令的子树快照恢复设施。
  实体/parent UUID 重映射，局部字段、兄弟顺序、资产 UUID 和普通字符串保持不变。
  当前反射没有 EntityReference；没有虚构通用引用重映射支持。
- InstantiatePrefabCommand 一条历史，Redo 固定首次快照/UUID；恢复失败清理全部新实体，
  UUID 冲突和重复主相机/Canvas 失败不改变原场景。事务内进行保守撤销内存预留。
- ProjectSession 导出新文件、原子保存资产注册表并发布内存状态；写失败回收新文件。
  Export 不改变 Scene dirty/history，Runtime/事务/恢复锁由 session 强制执行。
- Hierarchy 的 Export Prefab、Assets 的 Prefab 筛选和 Instantiate Prefab；MCP 同等
  authoring 入口，SceneSave/SceneWrite 分类和既有主线程权限链。
- Game 的 Robot.prefab、PrefabRobot.lua、PrefabShowcase.scene；机器人根包含 Sprite、
  Lua 和 Animator，Badge 子节点验证层级复用。没有引入依赖或新图像资产。

## 真实进程

CTest 中 MCP.Prefab.modern / legacy 使用现有 test-only FakeRenderDevice host，复用
生产 handlers。自动复制 Game，更改副本 defaultScene，完成导出、事务实例化/回滚、
两次实例化、资产/parent 检查、保存、退出重开、运行拒写、60 次 neutral Step、
独立 Lua/Animator 行为、Runtime Transform 与作者态隔离、Stop 后文件不变。

另外使用 `out/prefab-native-editor.py` 对同一外部脚本适配启动参数，实际启动：

```text
out/build/windows-msvc-debug/Editor/JanusEditor.exe --project <temporary Game copy> --mcp-stdio
```

两种协议时代均完整通过（out/prefab-native-editor.log），覆盖实际生产 Editor、
OpenGL 初始化和 owner-thread MCP 泵。辅助脚本隐藏启动窗口，不注入输入或改生产路径。
此记录是进程/功能验收，没有将它宣称为人工面板点击、视觉布局或真实音频听感验收。

## 边界

实例展开为普通 Scene 实体，无来源连接、嵌套 Prefab、override/apply/revert、传播或
runtime spawn。新注册模板实例化检查非空资产引用的身份和类型，不保证依赖文件内容
可用；各资产 loader/Runtime 保持正常内容错误语义。导出文件与 registry 并非跨文件
崩溃事务；崩溃间隙可能留未注册孤立文件。上述限制与设计一致。
整合小游戏、Human 实机操作、真实设备与 CPU 性能基线继续归入 10-10。
