## 依据与结论

依据用户本轮提供的 1672×941 参考图、仓库[图标集成截图](images/editor-icons-final.png)
（1707×1019）、当前 Editor 源码、PRD §10/14/15/20 与既有首版 UX 设计。
开始检查时 Git 工作区干净；本轮未修改实现、项目资产或产品范围。
通过 Computer Use 枚举窗口，当前没有运行中的 Janus；没有进行新的原生交互验收。
截图尺寸、内容和 DPI 条件不同，以下尺寸只用于归一化构图分析，不能用于判断字体栅格质量。

结论：主要分区已经接近参考图。剩余差距集中于控件视觉层次、Inspector 信息表达、
Scene 编辑反馈、资源卡片，以及示例美术。继续增加图标数量不是主要改进方向。
布局完成不等于交互完成；示例美术差异也不能当成渲染或物理系统缺失。

## 不能把参考图中的所有元素当作已批准功能

1. **场景美术**：参考图中树、山、天空、平台和角色占据大面积画面。当前 Integrated 是机器人战斗验收内容，
   使用简单角色、地面和背景。建议保留它作为集成验证场景，另做有代表性的美术展示场景。
   使用现有 Sprite/层级组合即可探索视觉呈现，不因此承诺新增 Tilemap 或灯光系统。
2. **二维模型**：Janus Transform 是 Vector2 position/scale 和一个 rotationRadians。
   参考图中的 XYZ、Static、Tag/Layer 不应作为纯皮肤工作照搬。显示标签可改，Scene v1 内部字段不能改名。
3. **脚本字段**：当前 LuaScriptComponent 只有 script/enabled；参考图里的 Health、Move Speed、Jump Force
   需要脚本可编辑属性元数据、验证和持久化设计。它们不是已有 Reflection 面板漏画几个输入框；Game 规则仍归 Game。
4. **碰撞体**：当前 Collider2D 使用 halfSize 等真实物理字段；参考图里的 Edit Shape 是新增视口交互。
   若 UI 展示全尺寸，需要明确与 halfSize 的换算，不能只改标签。
5. **操纵器**：PRD §10 将 Move Gizmo 列为必须支持；Rotate/Scale/Snapping 是后续项。
   不能为了填满工具栏一次性扩展全部功能，更不能放可点击但无行为的按钮。
6. **版本与状态**：参考图的 v0.6.0、FPS 144、Assets Up to date、MCP Connected 都不能当作当前工程事实。

## 推荐实施顺序

### A. 优先改善可见差距

统一面板/标签/按钮/输入框样式与文字层次；校准左右栏比例；整理主工具栏和 Hierarchy 顶部；
修复资源预览等比显示、整卡选中反馈；优化 Inspector 展示标签、轴名和单位。
这一批最直接影响截图观感，主要在 Editor 显示层，沿用现有图标和 Dear ImGui。
具体布局常量仍需实机校准，不要求自由 docking 或替换 UI 框架。

### B. 完成实际制作交互

先做 2D Move Gizmo，再做资源选择搜索/定位/拖入和诊断行详情。
移动须覆盖 X/Y/平面、父子坐标、预览取消、释放只提交一次、Undo/Redo、运行/事务只读；
继续经过 EditorActions → ProjectSession → CommandBus，不能为拖动直写作者态 ECS。
资源错误类型、丢失引用、取消选择不应改变原值。

### C. 独立提升展示场景

准备有前中后景、统一色板、合理画面占比的美术场景，再与参考图进行视觉比较。
不以换美术掩盖工具交互缺失，也不把该场景自动扩展为 v0.11 游戏交付。

发布顺序与视觉顺序分开：已知 PM-01 未保存关闭保护依旧是发布阻断项，不能被视觉工作替代。
