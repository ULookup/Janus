# Janus v0.1 Engine Foundation 收口设计

## 1. 背景与目标

Janus 已完成工程基线：Windows/MSVC Preset、Engine/Sandbox 目标分离、SDL3 窗口、日志、显式 `Result`、Catch2/CTest 和 Windows CI 均可用。但详细路线图定义的 v0.1 仍缺少 Application/MainLoop、时间、事件、键盘输入、文件系统工具和 OpenGL Context。

本阶段的目标是完成 v0.1 Engine Foundation，让 Sandbox 仅作为 Engine 公共 API 的客户端运行空窗口，并通过统一 Application 生命周期处理窗口事件、帧时间和输入状态。完成后才能进入 v0.2 Renderer2D。

## 2. 方案选择

考虑三种推进方式：

1. **先收口 Foundation，再进入 Renderer2D（采用）**：补齐 Application、Core 工具和平台事件边界，形成可测试的运行时宿主。短期可见画面仍是空窗口，但能避免 Renderer 直接依赖当前临时 Sandbox 循环。
2. **立即开始 Renderer2D**：更快获得图形结果，但 Application、事件和上下文所有权会在渲染代码进入后被迫重构，测试边界也更差。
3. **一次性建设通用 Scheduler、Layer System 和完整 Input Mapping**：未来扩展性强，但 v0.1 没有真实需求支撑这些抽象，且会提前侵入 v0.10 范围。

采用方案 1，并将工作限制在一个可独立验收的 v0.1 收口阶段。

## 3. 版本与文档边界

- PRD 负责产品目标、MVP 和用户闭环。
- 《Janus Engine 版本路线图》是版本编号、范围、Benchmark 和完成条件的唯一来源。
- v0.1 为 Engine Foundation；Renderer2D、Texture、Sprite 和 Camera 属于 v0.2。
- 本阶段不实现 Renderer、ECS、Scene、Asset、Lua、Editor 或 MCP。

## 4. 架构设计

### 4.1 Application 生命周期

新增 Engine 公共 `Application`，负责：

```text
Initialize Platform
        ↓
Create Window + OpenGL Context
        ↓
Client OnInitialize
        ↓
Poll Events → Update Input → Client OnEvent
        ↓
Measure Delta Time → Client OnUpdate
        ↓
Present Graphics Context
        ↓
Client OnShutdown
        ↓
Destroy Context/Window → Shutdown Platform
```

Sandbox 通过一个小型 `ApplicationClient` 实现接收生命周期回调，不直接调用 SDL、平台初始化或手写主循环。`Application::Run()` 返回 `Result<void>`，平台、窗口、上下文或客户端初始化失败时执行已完成资源的逆序清理。

首期使用固定执行顺序，不引入 Layer、Scheduler、Service Locator 或全局 `Application` 单例。

### 4.2 时间

Core 提供 `TimeStep` 值类型和基于 `std::chrono::steady_clock` 的 `FrameClock`：

- `TimeStep` 保存秒数并提供秒/毫秒访问；
- `FrameClock::Tick()` 返回上一帧到当前帧的时间；
- 第一帧返回零；
- Application 将单帧时间裁剪到最多 250 毫秒，避免调试断点或窗口拖动导致后续系统出现不稳定更新。

时间模块不依赖 SDL、窗口或 Renderer。

### 4.3 事件与键盘输入

公共事件模型使用有限的 `std::variant`，首期包含：

```text
WindowCloseEvent
WindowResizeEvent
KeyPressedEvent
KeyReleasedEvent
```

事件只包含 Janus 类型，不暴露 `SDL_Event` 或 SDL key code。`KeyCode` 首期覆盖 Escape、Space、Enter、方向键、W/A/S/D 和数字键；未知 SDL 按键不生成键盘事件。`Window::PollEvents` 将平台事件转换为 Janus 事件并提交给调用方。

Application 拥有非全局 `InputState`。每帧开始时清除瞬时状态，随后按事件更新：

- `IsKeyDown`：按键当前是否按下；
- `WasKeyPressed`：本帧是否从未按下变为按下；
- `WasKeyReleased`：本帧是否释放；
- SDL 自动重复只产生 `KeyPressedEvent`，但不重复触发 `WasKeyPressed`。

这里只提供物理键状态；动作映射属于 v0.10，不进入本阶段。

### 4.4 Window 与 OpenGL Context

平台层继续封装 SDL。v0.1 只有 OpenGL 一种图形后端，不增加仅有单一取值的图形 API 枚举。SDL backend 创建窗口时设置 OpenGL flag，并通过独立的 `GraphicsContext` 接口管理：

- context 创建与销毁；
- make current；
- swap interval；
- buffer present。

公共 API 不暴露 `SDL_Window*`、`SDL_GLContext`、`GLuint`、`GLenum` 或 `gl*` 调用。context 创建或 make-current 失败会终止初始化；默认请求 VSync，swap interval 设置失败只记录 warning 并继续运行。v0.1 仅建立上下文和交换缓冲；OpenGL 函数加载、RenderDevice 和绘制命令留给 v0.2。

### 4.5 FileSystem Utility

Core 提供基于 `std::filesystem` 的小型同步文件工具：

- 读取文本文件；
- 读取二进制文件；
- 写入文本文件；
- 写入二进制文件；
- 查询文件是否存在。

读取和写入返回 `Result`，错误包含路径与操作上下文。首期不实现虚拟文件系统、挂载点、异步 IO、Asset 路径或原子 Scene 保存；这些属于后续版本。

## 5. 所有权与依赖

```text
Sandbox → Application public API
Application → Core Time/Event/Input + Platform Window/Context
SDL backend → SDL3
Core Time/Event/Input/FileSystem → C++ standard library only
```

所有权固定为 `Application` 拥有 Window、GraphicsContext、InputState 和客户端生命周期。上下文必须早于窗口销毁，窗口必须早于 SDL 平台关闭。

## 6. 错误处理

- 可恢复初始化和 IO 错误通过 `Result<T>` 返回，不使用异常作为流程控制。
- 为 OpenGL context、swap interval 和文件 IO 补充聚焦的 `ErrorCode`。
- `Application::Run()` 在失败路径执行确定性的逆序清理并返回原始错误。
- 运行中的不可恢复平台错误请求退出，并保留日志；普通未知事件被忽略。
- 日志初始化失败不得导致空 logger 解引用；日志访问需拥有安全的 fallback 或显式初始化保证。

## 7. 测试与验证

自动测试保持无显示器、无窗口和无 GPU 依赖：

- `TimeStep` 单位转换、首帧行为和 delta 裁剪；
- 事件 variant 的类型与数据；
- `InputState` 的按下、保持、释放、逐帧瞬时状态和重复键行为；
- FileSystem 文本/二进制 round trip、缺失文件和无效父路径错误；
- Window 配置的纯验证逻辑；
- Application 生命周期顺序通过 Engine 内部 factory seam 注入测试替身验证；该 seam 不进入 Engine 公共 API，也不启动真实 SDL 窗口。

手动运行 Sandbox 验证：窗口可创建、关闭、缩放，并可通过一个约定按键请求退出。完整验收命令使用仓库现有两个配置/构建 Preset、CTest 和 `git diff --check`。

## 8. 交付顺序

1. Core Time 与 FileSystem，先建立纯单元测试。
2. Event、KeyCode 与 InputState，先验证平台无关状态机。
3. Window 事件输出和 SDL 翻译，保持 SDL 类型在 backend 内。
4. GraphicsContext 与 SDL OpenGL context，确定资源销毁顺序。
5. Application 生命周期，迁移 Sandbox 到公共 API。
6. 全量构建、测试、手动窗口验证和文档状态更新。

每一步都必须形成可审查、可测试的独立提交。若某一步需要 Renderer、ECS 或 Input Mapping 才能成立，应缩小实现而不是扩大 v0.1。

## 9. 完成条件

- Sandbox 只依赖 Engine 公共 API，不包含 SDL 或 OpenGL backend 类型。
- Application 统一管理平台、窗口、上下文、事件、输入、delta time 与关闭流程。
- 空窗口支持关闭、缩放和键盘输入。
- Core 不依赖 Renderer 或 SDL。
- 两套 Windows/MSVC Preset 配置和构建成功。
- `ctest --preset windows-msvc-debug-tests` 零失败。
- 自动测试不要求显示器或 GPU。
- README、PRD、技术架构和版本路线图对 v0.1/v0.2 边界一致。
- `git diff --check` 无错误，生成目录保持忽略。

## 10. 非目标

- OpenGL 函数加载与任何绘制命令；
- RenderDevice、Shader、Texture、Framebuffer、Camera、Sprite 或 batching；
- ECS、Scene、Asset、Serialization、Lua、Editor、MCP；
- Layer、Scheduler、Job System、Input Mapping、游戏手柄或鼠标映射；
- Linux/macOS 支持扩展；
- 新的第三方依赖。
