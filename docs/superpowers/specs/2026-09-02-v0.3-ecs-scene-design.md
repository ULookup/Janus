# Janus v0.3 ECS + Scene Design

## 1. Background and Goal

Janus has completed v0.1 Engine Foundation and v0.2 Renderer2D. The current verified baseline:

- Application lifecycle, SDL3 window, OpenGL 4.5 Core Context, events, keyboard input, frame time, file system, logging, and tests are in place.
- Renderer2D provides a public immediate-mode API, internal `RenderDevice`, RenderQueue, BatchRenderer, renderer statistics, and a private OpenGL backend.
- CTest reports 33/33 tests passing.
- Sandbox currently submits every `Sprite` directly to `Renderer2D`.

The next milestone is v0.3 ECS + Scene. The goal is to introduce a real game-world runtime:

- `Entity` uses index + generation.
- `SparseSet` and `ComponentPool` provide dense component storage.
- `Registry` owns entities and components and provides `View<T...>` queries.
- `Scene` owns a `Registry` and hierarchy.
- `TransformComponent`, `SpriteRendererComponent`, and `CameraComponent` connect world state to the existing Renderer2D pipeline.
- `Application` owns a `Scene` and automatically renders it after the client update.

After v0.3, Sandbox should populate and mutate a Scene. It must no longer call `Renderer2D::SubmitSprite` for every rendered object.

## 2. Scope

In scope:

- `ECS::Entity` with stable generation.
- `ECS::SparseSet`.
- `ECS::ComponentPool<T>`.
- `ECS::Registry`.
- `ECS::View<T...>`.
- `Scene`.
- `HierarchyComponent` and `Scene::SetParent`.
- `TransformComponent` with local/world transform cache.
- `SpriteRendererComponent`.
- `CameraComponent`.
- Scene-to-Renderer2D submission.
- Sandbox demo using Scene.
- ECS and Scene benchmarks.

Out of scope:

- Asset system, serialization, UUID, `AssetHandle`.
- Lua scripting.
- Editor, MCP, reflection, command bus.
- Physics, animation, audio, UI.
- Prefab, scene serialization, play-mode scene cloning.
- 3D, Vulkan, render graph, job system.
- Texture import or stb_image.

## 3. Key Decisions

1. ECS primitives live under `Janus::ECS` and depend only on Core.
2. `Scene` is a public `Janus` type and depends on ECS and Renderer public types.
3. `Scene::Render` is the only normal path from scene state to `Renderer2D::SubmitSprite` in v0.3.
4. Components are plain data. Systems are free functions or `Scene` methods, not component methods.
5. `Registry` uses type-erased component pools internally; template APIs remain public.
6. `View<T...>` uses `ForEach` and iterates the first requested component pool; it does not add runtime smallest-pool selection until a benchmark proves it is needed.
7. `Scene::CreateEntity` automatically adds `TransformComponent` and `HierarchyComponent`.
8. Hierarchy uses a relationship component with parent/first-child/next-sibling/previous-sibling links.
9. Transform propagation is top-down, lazy, and dirty-flag based.
10. `SpriteRendererComponent` stores renderer-visible data only. Transform provides position, rotation, and scale.
11. `CameraComponent` is selected by `primary` first, otherwise the first matching entity.
12. v0.3 does not introduce names, UUIDs, or scene serialization.

## 3.1 Reference Engine Mapping

Janus should not invent a proprietary ECS/Scene model from first principles. v0.3 follows established patterns from mature engines and applies them only where they fit a small 2D engine.

### Godot

Godot separates the optional SceneTree/Node layer from low-level Servers. Rendering, physics, and audio servers expose opaque RIDs and are the real implementation layer; the scene tree is a convenience layer on top.

Janus mapping:

- `Renderer2D` is the v0.3 analogue of Godot's `RenderingServer` CanvasItem API.
- `Scene` is the high-level scene layer that submits into `Renderer2D`.
- Texture and render resources are already opaque handles, similar to Godot RIDs.

Implication: Scene code should not call OpenGL or backend types. It should only consume the Renderer2D public contract.

### Unity

Unity has two relevant models:

- Classic GameObject/Component/Transform, where every GameObject has a Transform and hierarchy is expressed through parenting.
- Unity DOTS/Entities, which stores unmanaged component data in contiguous storage and queries entities through archetypes or sparse sets.

Janus mapping:

- `TransformComponent` is mandatory for Scene-created entities, matching Unity's "every GameObject has a Transform".
- `ECS::Entity` uses index + generation, matching Unity/DOTS and Unreal Mass's stable handle approach.
- v0.3 uses a sparse set + dense component array, matching the EnTT/Unity sparse-set direction and keeping the first ECS implementation testable.

Implication: Keep components data-only and keep query APIs separate from per-object virtual dispatch.

### Unreal Engine

Unreal's classic Actor model uses SceneComponents that own transforms and attach into hierarchies. Its Mass Entity framework goes further: Fragments, Archetypes, Chunks, Processors, EntityQuery, and MassCommandBuffer are all built around data-oriented processing.

Janus mapping:

- `TransformComponent` corresponds to the transform-bearing SceneComponent concept.
- `SpriteRendererComponent` and `CameraComponent` are data fragments, not Actor subclasses.
- `Scene::Render` is a small fixed processor/query: find cameras, update transforms, submit sprites.
- Deferred structural changes (MassCommandBuffer) are intentionally deferred to v0.7 CommandBus, not bolted onto v0.3.

Implication: v0.3 should expose deterministic queries and stable handles now, so CommandBus/MCP can reuse them later.

## 3.2 AI Native Design Principles

Janus is not a Unity/Godot/Unreal clone. Its differentiator is that an AI Agent is a first-class engine client, not a file-system side effect. Therefore the ECS/Scene layer must be designed for future Agent use even before MCP is implemented.

For v0.3, this means:

1. `ECS::Entity` is a stable, inspectable value: `index + generation`, not a raw pointer.
2. Component data is plain, reflection-friendly structs; no hidden virtual object graph.
3. `Scene` exposes explicit queries: `HasComponent<T>`, `GetComponent<T>`, and `View<T...>`, while keeping its mutable `Registry` private.
4. `Scene::CreateEntity`, `Scene::DestroyEntity`, and `Scene::SetParent` are the future CommandBus verbs.
5. Hierarchy is explicit and traversable, so an Agent can reconstruct a scene tree without reading renderer internals.
6. `Scene::Render` is deterministic and side-effect constrained; world transform caches are derived data, not authoring state.
7. Renderer statistics remain separate from Scene authoring state, so Agent queries and rendering telemetry do not conflate concerns.
8. Direct `ECS::Registry` use remains possible for advanced clients, but normal Agent/Editor/Game usage goes through `Scene::CreateEntity` and Scene mutation methods.

This keeps v0.3 within scope while ensuring the later Reflection, CommandBus, MCP Resource, and MCP Tool layers can be built on the same ECS/Scene surface.

## 4. Architecture

```text
Sandbox / future Editor / future Game
              |
              v
        Application
          |    |
          |    +----------------------+
          |                           |
          v                           v
        Scene                     Renderer2D
          |                           |
          v                           |
      ECS::Registry                   |
          |                           |
  +-------+--------+                  |
  |                |                  |
SparseSet     ComponentPool           |
                                      |
                                      v
                                  RenderQueue
                                      |
                                      v
                                  BatchRenderer
                                      |
                                      v
                                  RenderDevice
                                      |
                                      v
                              OpenGLRenderDevice
```

Application creates and owns both `Renderer2D` and `Scene`. The client updates the Scene through Application APIs. Application then asks Scene to render into Renderer2D. This removes renderer submission from Sandbox while preserving Renderer2D as an Engine public capability for future clients.

## 5. Public API Design

### 5.1 Entity

```cpp
namespace Janus::ECS
{

struct Entity
{
    static constexpr u32 InvalidIndex = 0xFFFFFFFFu;

    u32 index = InvalidIndex;
    u32 generation = 0;

    [[nodiscard]]
    bool IsValid() const noexcept
    {
        return index != InvalidIndex && generation != 0;
    }

    auto operator<=>(const Entity&) const = default;
};

} // namespace Janus::ECS
```

Generation starts at `1`, so `Entity{}` is an invalid sentinel. An `Entity` is a value type and remains safe to store after destruction; Registry lookup validates both index and generation.

### 5.2 SparseSet

```cpp
namespace Janus::ECS
{

class SparseSet
{
public:
    [[nodiscard]] bool Contains(Entity entity) const noexcept;
    [[nodiscard]] u32 DenseIndex(Entity entity) const noexcept;
    [[nodiscard]] const std::vector<Entity>& Entities() const noexcept;

    bool Add(Entity entity);
    void Remove(Entity entity);

private:
    static constexpr u32 InvalidDenseIndex = 0xFFFFFFFFu;

    std::vector<Entity> m_Sparse;
    std::vector<u32> m_SparseToDense;
    std::vector<Entity> m_Dense;
};

} // namespace Janus::ECS
```

`SparseSet` uses swap-and-pop removal. It is the storage base for `ComponentPool<T>`.

### 5.3 ComponentPool

```cpp
namespace Janus::ECS
{

template <typename T>
class ComponentPool final : public IComponentPool
{
public:
    [[nodiscard]] bool Has(Entity entity) const noexcept;
    [[nodiscard]] T* Get(Entity entity) noexcept;
    [[nodiscard]] const T* Get(Entity entity) const noexcept;
    T* Add(Entity entity, T component);
    void Remove(Entity entity) override;
    [[nodiscard]] const std::vector<Entity>& Entities() const noexcept;

private:
    SparseSet m_Sparse;
    std::vector<T> m_Components;
};

} // namespace Janus::ECS
```

`ComponentPool<T>` stores one component per entity in the same order as the dense entity list.

### 5.4 Registry

```cpp
namespace Janus::ECS
{

class Registry
{
public:
    [[nodiscard]] Entity CreateEntity();
    bool DestroyEntity(Entity entity);
    [[nodiscard]] bool IsValid(Entity entity) const noexcept;
    [[nodiscard]] usize AliveEntityCount() const noexcept;

    template <typename T>
    T* AddComponent(Entity entity, T component);

    template <typename T>
    bool RemoveComponent(Entity entity);

    template <typename T>
    [[nodiscard]] T* GetComponent(Entity entity) noexcept;

    template <typename T>
    [[nodiscard]] const T* GetComponent(Entity entity) const noexcept;

    template <typename T>
    [[nodiscard]] bool HasComponent(Entity entity) const noexcept;

    template <typename... Components>
    [[nodiscard]] View<Components...> View();

private:
    std::vector<u32> m_Generations;
    std::vector<u32> m_FreeIndices;
    std::unordered_map<std::type_index, std::unique_ptr<IComponentPool>> m_Pools;
    usize m_AliveCount = 0;
};

} // namespace Janus::ECS
```

Destroying an entity removes it from every component pool, increments its generation, and returns its index to the free list.

### 5.5 View

```cpp
namespace Janus::ECS
{

template <typename... Components>
class View
{
public:
    template <typename Function>
    void ForEach(Function&& function) const;

private:
    explicit View(std::tuple<ComponentPool<Components>*...> pools);

    std::tuple<ComponentPool<Components>*...> m_Pools;
    const std::vector<Entity>* m_PrimaryEntities = nullptr;

    friend class Registry;
};

} // namespace Janus::ECS
```

`ForEach` iterates the first requested component pool, then invokes `function(entity, components...)` for every entity present in all requested pools.

Example:

```cpp
registry.View<TransformComponent, SpriteRendererComponent>()
    .ForEach([](ECS::Entity, TransformComponent& transform,
                SpriteRendererComponent& sprite)
    {
        // ...
    });
```

### 5.6 Components

```cpp
namespace Janus
{

struct TransformComponent
{
    Vector2 position;
    f32 rotationRadians = 0.0f;
    Vector2 scale{1.0f, 1.0f};

    Vector2 worldPosition;
    f32 worldRotationRadians = 0.0f;
    Vector2 worldScale{1.0f, 1.0f};
    bool dirty = true;
};

struct SpriteRendererComponent
{
    TextureHandle texture;
    Vector2 size{1.0f, 1.0f};
    Color color = Color::White();
    i32 layer = 0;
    TextureRegion uv = TextureRegion::Full();
    bool enabled = true;
};

struct CameraComponent
{
    f32 zoom = 1.0f;
    bool primary = false;
};

} // namespace Janus
```

### 5.7 HierarchyComponent

```cpp
namespace Janus
{

struct HierarchyComponent
{
    ECS::Entity parent = ECS::Entity{};
    ECS::Entity firstChild = ECS::Entity{};
    ECS::Entity nextSibling = ECS::Entity{};
    ECS::Entity previousSibling = ECS::Entity{};
};

} // namespace Janus
```

`Scene::SetParent` maintains these links and rejects cycles and self-parenting.

### 5.8 Scene

```cpp
namespace Janus
{

class Scene
{
public:
    Scene();
    ~Scene();

    Scene(const Scene&) = delete;
    Scene& operator=(const Scene&) = delete;

    [[nodiscard]] ECS::Entity CreateEntity();
    bool DestroyEntity(ECS::Entity entity);
    [[nodiscard]] Result<void> SetParent(
        ECS::Entity child,
        ECS::Entity parent);

    [[nodiscard]] const ECS::Registry& GetRegistry() const noexcept;

    template <typename T>
    T* AddComponent(ECS::Entity entity, T component);

    template <typename T>
    [[nodiscard]] T* GetComponent(ECS::Entity entity) noexcept;

    template <typename T>
    [[nodiscard]] const T* GetComponent(
        ECS::Entity entity) const noexcept;

    template <typename T>
    [[nodiscard]] bool HasComponent(
        ECS::Entity entity) const noexcept;

    template <typename... Components>
    [[nodiscard]] ECS::View<Components...> View();

    [[nodiscard]] Result<void> Render(
        Renderer2D& renderer,
        Viewport viewport);

private:
    void UpdateTransforms();
    void UpdateTransformRecursive(
        ECS::Entity entity,
        const Mat4& parentWorld,
        f32 parentWorldRotation,
        Vector2 parentWorldScale,
        bool parentDirty);

    [[nodiscard]] Result<ECS::Entity> FindCamera();

    void DetachFromParent(ECS::Entity entity);
    void DestroyEntityRecursive(ECS::Entity entity);

    ECS::Registry m_Registry;
};

template <typename T>
T* Scene::AddComponent(ECS::Entity entity, T component)
{
    return m_Registry.AddComponent<T>(
        entity,
        std::move(component));
}

template <typename T>
T* Scene::GetComponent(ECS::Entity entity) noexcept
{
    return m_Registry.GetComponent<T>(entity);
}

template <typename T>
const T* Scene::GetComponent(
    ECS::Entity entity) const noexcept
{
    return m_Registry.GetComponent<T>(entity);
}

template <typename T>
bool Scene::HasComponent(
    ECS::Entity entity) const noexcept
{
    return m_Registry.HasComponent<T>(entity);
}

template <typename... Components>
ECS::View<Components...> Scene::View()
{
    return m_Registry.View<Components...>();
}

} // namespace Janus
```

`Scene::Render` performs:

1. `FindCamera`.
2. `UpdateTransforms`.
3. `renderer.SetViewport(viewport)`.
4. `renderer.BeginFrame(camera)`.
5. Submit every enabled `SpriteRendererComponent` with its world transform.
6. `return renderer.EndFrame()`.

## 6. Transform Propagation

`TransformComponent` stores local and world position/rotation/scale plus a dirty flag. `Scene::UpdateTransforms` walks root entities and recurses through `HierarchyComponent::firstChild`.

For each entity:

```cpp
const Mat4 local = Mat4::Multiply(
    Mat4::Translate(transform.position),
    Mat4::Multiply(
        Mat4::Rotate(transform.rotationRadians),
        Mat4::Scale(transform.scale)));

const Mat4 world =
    Mat4::Multiply(parentWorld, local);
```

World position/rotation/scale are computed explicitly because `Mat4` is a 2D transform helper and does not expose arbitrary matrix decomposition:

```cpp
worldPosition = Mat4::TransformPoint(parentWorld, local.position);
worldRotationRadians =
    parentWorldRotation + local.rotationRadians;
worldScale = {
    parentWorldScale.x * local.scale.x,
    parentWorldScale.y * local.scale.y};
```

The parent world matrix is passed through recursion but is not stored on every component. A child is recomputed when it is dirty or any ancestor is dirty.

## 7. Scene to Renderer Mapping

`SpriteRendererComponent` maps to the existing `Sprite` type:

```cpp
Sprite sprite;
sprite.texture = component.texture;
sprite.position = transform.worldPosition;
sprite.size = {
    component.size.x * transform.worldScale.x,
    component.size.y * transform.worldScale.y};
sprite.rotationRadians = transform.worldRotationRadians;
sprite.color = component.color;
sprite.layer = component.layer;
sprite.uv = component.uv;
sprite.blendMode = BlendMode::Alpha;
```

`CameraComponent` maps to `OrthographicCamera`:

```cpp
OrthographicCamera camera;
camera.position = transform.worldPosition;
camera.rotationRadians = transform.worldRotationRadians;
camera.zoom = cameraComponent.zoom;
```

## 8. Application Integration

Application creates and owns `Scene` after `Renderer2D` creation and before `ApplicationClient::OnInitialize`.

The loop becomes:

```text
Poll events and input
     |
Measure delta time
     |
Client OnUpdate
     |
Scene::Render(renderer, viewport)
     |
Present graphics context
```

`Application::GetScene()` exposes the scene. `Application::GetRenderer2D()` remains available for texture creation and read-only statistics.

Cleanup order:

```text
Scene
  |
Renderer2D
  |
GraphicsContext
  |
Window
  |
Platform
```

## 9. Error Handling

Add `ErrorCode` values:

- `InvalidEntity`
- `EntityNotFound`
- `CameraNotFound`
- `HierarchyCycle`

Rules:

- `Registry::CreateEntity` returns an `Entity`; it does not allocate a component unless requested.
- `Registry::DestroyEntity` returns `false` for an invalid or already-destroyed entity.
- `Scene::CreateEntity` returns `Entity`; entity allocation is not a recoverable engine error.
- `Scene::DestroyEntity` returns `false` for an invalid or already-destroyed entity.
- `Scene::SetParent` reports `InvalidEntity`, `EntityNotFound`, or `HierarchyCycle`.
- `Scene::Render` reports `CameraNotFound` or the underlying `Renderer2D::EndFrame` failure.
- Component getters return `nullptr` when the component is absent; they do not throw.
- Debug assertions are used only for programmer errors, not runtime scene state.

## 10. Lifetime and Ownership

Ownership:

```text
Application
  owns Window
  owns GraphicsContext
  owns Renderer2D
  owns Scene
```

`Scene` owns its `Registry`. Components and entities are owned by the registry. `Scene` does not own GPU resources; texture handles are owned by `Renderer2D` until explicitly destroyed.

Destroying an entity recursively destroys its hierarchy subtree.

Entities intended for Scene rendering should be created through `Scene::CreateEntity`, which automatically adds the required Transform and Hierarchy components. `Scene` does not expose its mutable Registry, so normal clients cannot create raw entities or mutate pools behind Scene's back.

## 14. Acceptance Criteria

- Renderer no longer receives all sprites from Sandbox; `Scene::Render` submits scene sprites.
- Scene can create a Camera, Player, and Enemy entities.
- Hierarchy parent/child/sibling links are correct and reject cycles.
- Transform world positions, rotations, and scales propagate correctly.
- Scene renders using the primary or first camera.
- Scene exposes stable `ECS::Entity` handles and data-only component types.
- Scene API verbs (`CreateEntity`, `DestroyEntity`, `SetParent`) are explicit and deterministic enough to become future CommandBus operations.
- ECS and Scene automated tests pass.
- Both normal and test presets configure and build successfully.
- `ctest --preset windows-msvc-debug-tests` reports zero failures.
- ECS benchmark builds and runs.
- `git diff --check` reports no whitespace errors.

## 15. Risks

- View implementation complexity. Mitigation: use `ForEach` with a fixed first pool rather than custom iterators or dynamic pool selection.
- Hierarchy bugs. Mitigation: centralize link maintenance in `Scene::SetParent` and test cycles/subtrees.
- Transform cache invalidation. Mitigation: start with a simple top-down dirty propagation and keep world values explicit.
- Application test ordering changes. Mitigation: extend the existing dependency seam with `createScene` and update lifecycle assertions before integrating the loop.
- Scope creep into Asset/Serialization/Editor. Mitigation: keep v0.3 limited to ECS + Scene and defer those modules.
