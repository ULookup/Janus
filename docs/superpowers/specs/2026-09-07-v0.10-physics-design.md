# v0.10 10-08 Physics

## Scope and dependency

One shared CPU simulation stage in RuntimeExecution, using privately linked Box2D
3.1.1 at commit `8c661469c9507d3ad6fbd2fea3f1aa71669c2fe3` (MIT).
No backend handles escape Engine/Physics. Upstream samples, tests, benchmarks and
task libraries are not built. Engine tests exercise the real single-threaded solver.

Official references: [simulation](https://box2d.org/documentation/md_simulation.html),
[pinned API](https://github.com/erincatto/box2d/tree/v3.1.1/include/box2d).

## Authoring contract

RigidBody2D: type (`static`, `kinematic`, `dynamic`), enabled (default false),
gravityScale, fixedRotation. Collider2D: halfSize, density, friction, restitution,
isTrigger. An enabled body needs a collider and Transform. Physics entities must
be root nodes with unit scale; visual children are allowed. One world unit is one
metre, +Y is up, rotations are radians. Gravity is (0,-9.81). Only boxes in this
slice; joints, circles, layers, arbitrary hierarchy scaling and editors are deferred.
Both components use the active ReflectionRegistry, Scene v1 and existing commands.

## Execution and lifetime

RuntimeExecution starts physics before Lua OnCreate. Each Advance dispatches UI,
runs Lua Update once, advances physics at 1/60 second with four solver substeps,
then animation and audio. Catch-up is capped at eight ticks; excess whole ticks
are discarded, fractional time retained and dropped duration observable (saturates at 1e12 seconds). Lua input
edges are never replayed by catch-up. Neutral paused Step advances exactly one
tick without reload; pause performs no simulation. Stop discards native world,
velocities, events and accumulator; a new Start uses the supplied Scene poses.
Editor simulation only changes its cloned RuntimeScene.

Transform writes are teleports synchronized before stepping. Native poses flow
back to runtime Transform after every tick. Runtime velocity and impulse methods
are explicit, bounded and validate before invoking Box2D. Shape/body settings are
startup configuration; changing them during execution fails explicitly.

Contact/sensor events are copied to UUID pairs after the solver, sorted and
deduplicated before owner-thread delivery. Lua receives OnCollisionEnter/Exit or
OnTriggerEnter/Exit with the other Entity reference. Entity:destroy queues bounded
destruction; it never mutates a world during solver/event traversal. Destruction
flushes after a whole event batch (also after a callback failure), before another
tick. Pending entities/descendants receive no later Update or physics callbacks.
OnDestroy is invoked before removing their Scene entities, including visual descendants;
instances are released immediately. Requests queued by OnDestroy form the next batch. Removal cancels
their contact records without synthetic exit callbacks. No persistence or Undo
is involved. Callback failure uses existing Runtime Faulted retention.

Physics.raycast uses start/end points, returns the nearest hit or nil, excludes
triggers by default and ignores shapes containing the ray origin (Box2D behavior).
Queries and physics statistics are available to Lua; bounded diagnostic snapshots
reuse the existing RuntimeRead resource, without adding Agent input injection.

## Acceptance

Real-solver tests cover falling/blocking, trigger enter/exit, raycasts, kinematic
motion, impulses, invalid content, catch-up bounds, destruction, pause/step and
restart. Shared execution tests cover Lua callbacks, fault retention and authoring
isolation. An independent PhysicsShowcase scene demonstrates these systems.
Prefab (10-09) and integrated v0.10 acceptance remain subsequent packages.

## Lua API and bounds

- `entity:set_velocity(x,y)` / `entity:get_velocity()` use metres per second; setters
  require a movable body and components within +/-100. `entity:apply_impulse(x,y)`
  requires a dynamic body and components within +/-100 N.s.
- `entity:set_position(x,y)` teleports physical bodies immediately for same-callback
  raycasts, without resetting velocity. Direct runtime Transform edits synchronize
  before the next tick. World positions and rotation input are finite within +/-10000.
- `entity:destroy()` is available only through managed execution. Repeated requests
  in a batch are idempotent. References become stale after the safe flush.
- `Physics.raycast(x1,y1,x2,y2,includeTriggers=false)` returns nil or a table with
  entity, x, y, normalX, normalY, fraction. Equal-distance hits break ties by UUID.
- `Physics.stats()` returns completed ticks, dropped seconds, live body count.
  Lua Update snapshots observe the prior completed tick; event callbacks observe
  the new tick. Both carry the existing attempted outer-frame publication metadata.
- Up to 1024 active bodies / queued roots and 4096 raw contact/sensor events per tick.
  halfSize and density are [0.01,100], material friction/restitution [0,1],
  gravityScale [-10,10]. Sensors use discrete overlap detection, not continuous sweeps.
- No guarantee of bitwise determinism across different CPUs/builds. Same-build host
  equivalence is tested with identical input and frame durations.
