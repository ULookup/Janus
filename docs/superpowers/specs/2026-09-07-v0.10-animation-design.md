# v0.10 / 10-06 AnimationClip 与 Animator

## 边界

承接本地 10-05b（未提交），在 codex/v0.10-animation 保留全部战斗包改动。
按 PRD §18 和路线图实现 Sprite 帧动画，不做状态机、骨骼、动画编辑器或物理调度。
没有新依赖。帧材质为注册 Texture atlas + normalized UV，亦可驱动同实体 UI Image。

## 资产与作者态

AnimationClip v1（asset type `animation-clip`）为 JSON：version=1、texture UUID、loop bool、
frames 数组，每帧 uvMin/uvMax、duration（秒）。最多 1024 帧、1 MiB 文件、每帧
0.001–60 秒、总时长 <=3600 秒；UV 有限、在 [0,1] 内且正面积。非法/缺失资源显式失败。
AssetCache 缓存 CPU Clip；AssetService 校验 Texture 注册类型并管理失效，无第二份 GPU 纹理。
卸载 atlas 同时失效相关 clip；运行时不保留指向缓存的裸指针。

Animator 作者态字段：clip、enabled、playOnStart、speed（0–100，0 冻结）。添加组件默认
disabled，允许先添加后配置；启用需要非空 animation-clip 引用，并且运行时要求同实体
恰有一个 SpriteRenderer 或 Image。通过 active Reflection、Scene v1、Clone、Command、
Inspector、MCP schema 统一编辑，不序列化 frame/time/playing。

## 唯一执行路径

RuntimeExecution 拥有 AnimationSystem：Start 清理旧状态、加载配置并采样第 0 帧，随后
Lua OnCreate；Advance 依次 UI 输入消费、reload、OnClick、Lua Update、Animation Advance。
脚本可在当前 Update 调用 entity:play_animation([clip UUID])、stop_animation()；无参数播放
配置 clip，有参数切换并从 0 重播。失败不覆盖旧播放状态。animation_state() 返回
playing/frameIndex（0-based）/elapsedSeconds，可由 Game 发布到快照。

AnimationSystem 以实体 UUID 保存游标和帧 pose。Renderer 只读 pose 覆盖 texture/UV，
不改 Sprite/Image 作者字段。Stop 动画恢复原始 Sprite/Image；非循环自然结束保留最后帧、
playing=false；循环按总时长取余，不逐次补帧，超大 dt 有界。边界时刻选择下一帧。
UILayout 可选读取同一 AnimationSystem，基础贴图为空而动画提供纹理的 Image 也参与一致的绘制/命中顺序。
新播放在发起帧保持第 0 帧，从下一 Advance 消耗 dt；自动播放在首个 Update 正常推进。
组件被移除/禁用、实体销毁或目标失效时回收状态；更换作者 clip/playOnStart 时重新初始化。
Pause 不推进；Step 推进 1/60，不自动重载已播放的 clip（复用运行快照），Stop 清理。
每次播放持有 Clip 的 CPU 值副本；明确重新 Play/Switch 才应用卸载后重新加载的 clip 内容。
新 Runtime Start 卸载配置的 clip 缓存，读取最新磁盘数据。Lua 故障保留旧 pose 和 Faulted 世界。
