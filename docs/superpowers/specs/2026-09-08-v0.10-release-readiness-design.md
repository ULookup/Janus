## 2. 现有代码约束与新增边界

- `ApplicationClient::OnEvent` 返回 void；`Application::Run` 先处理关闭再通知 Client。
  `SDLWindow::PollEvents` 又先设置 `ShouldClose`。仅加 ImGui 弹窗无法取消退出。
- `ProjectSession` 持有 Scene、Reflection、AssetService、CommandBus；命令引用 Scene，
  AssetService 引用 Registry/Renderer，MCP host 当前持有 `ProjectSession&`。
- MCP 在 `Pump()` 开头检查 Scene revision，一次 Pump 可执行多条请求。加入场景切换后，
  仅在帧开头刷新不足以保护同一批内的下一条请求。
- Scene 保存已有 `Serialize → WriteTextAtomic`；Windows 使用替换式原子 rename。
  新文件的“不能覆盖”还需要文件系统层的 create-only 提交语义，不能只在 UI 判断 exists。
- `EntitySubtreeSnapshot` 已位于 `Scene/Command/EntityCommands.h`，Prefab 已使用它。
  Duplicate 复用这条路径，不建立第二套组件序列化。
- 当前 Renderer 遍历后会更新 Transform 的 world 缓存。拖动预览必须单独计算临时结果，
  不能将预览值写进 local 字段或 world 缓存再尝试还原。

新增职责限定如下，不建立全局 Manager，也不添加第三方依赖：

| 所在层 | 建议新增职责 |
| --- | --- |
| Platform/Application | 区分可拒绝的窗口关闭请求与已确认的退出；保持无 Editor 客户端默认行为 |
| JanusEditorCore | 可测试的离开流程、属性草稿、偏好模型、拖动状态模型；不依赖 ImGui |
| ProjectSession | 生命周期写入保护、条件提交、单场景替换；延续 Runtime/事务/recovery guards |
| Engine/Scene | Duplicate 共享命令、子树 UUID 重映射、只读世界姿态计算和预览输入 |
| Editor MCP host | 每请求绑定刷新、会话代数检查、项目重绑定；协议线程不访问作者态 |
| Core/FileSystem | 同目录临时文件的 replace/create-only 提交选择；平台代码留在实现中 |

## 3. A 包：未保存关闭保护（原 R1）

### 3.1 可取消的应用关闭契约

建议新增 `ApplicationClient::OnCloseRequested(Application&) -> CloseDecision`，
返回 `Accept` 或 `Defer`，默认 Accept。Defer 表示客户端负责后续确认或取消，应用继续帧循环。
Editor 只在已获确认时调用现有 `Application::RequestExit()`；该方法保留最终退出语义，
不将所有内部错误退出改成可取消流程。

SDL 的系统关闭事件只发布 `WindowCloseEvent`，不预先设置 `m_ShouldClose`。
保留 `Window::RequestClose()` 为宿主明确确认关闭的原有接口，所有原生/测试客户端逐一核对。
Application 在窗口关闭事件时调用新 hook；Accept 才 RequestExit，普通 OnEvent 仍只通知一次。
菜单 Exit 直接进入与该 hook 相同的 Editor 控制器。重复 X/Alt+F4 合并为一个待决请求。
明确确认后不再执行新的作者态操作或 MCP Pump；是否保留普通客户端原有最后一帧行为由测试固定。
正常错误返回、初始化失败和 OS 强制终止不进入保存对话框；不承诺断电/强制杀进程恢复。

### 3.2 离开控制器与状态

建议 `EditorLeaveController` 持有唯一 `LeaveIntent`：Exit、NewScene、OpenScene、OpenProject。
意图只包含值类型路径和代数，不保存指向当前 Scene 的裸引用。R1 先实现 Exit，其余在 E 包接入。
ImGui 只绘制状态和提交选择；控制器在 owner thread 推进一步，可用假保存/停止结果测试。

```text
Idle → SettleInteraction → Review → ApplyDecisions → PerformIntent → Idle / ExitAccepted
                            ↑              |
                            └── Error ─────┘
Review / Error --Cancel--> Idle
```

Review 同时展示当前 Runtime、Scene dirty、设置草稿、事务/recovery 情况，默认焦点为 Cancel。
先收齐选择，再执行 Stop/保存，避免用户尚未确认全部意图便发生副作用。
保存失败后的取消保留窗口和未保存内容；已明确执行的 Stop 或成功设置保存不逆向恢复，UI 必须说明。

| 当前情况 | 允许的选择与行为 |
| --- | --- |
| 干净、无草稿、Stopped | 直接确认退出 |
| dirty Scene | Save and Exit / Discard and Exit / Cancel；Discard 不先清 dirty，直到真正离开才销毁 |
| Playing / Paused / Faulted | 明确 Stop and Continue 或 Cancel；保存对象始终是 EditorScene |
| 设置草稿未应用 | 独立 Save Settings / Discard Draft / Cancel；Scene Save 不保存设置 |
| 活动 Agent 事务 | 显示等待/取消离开，或 Human 明确“回滚该事务并继续”；不自动 Commit |
| 事务回滚失败/recovery | 禁止 Save；Human 可显式放弃作者态并退出，或取消后使用现有 Discard/Reload；不能把坏状态保存出去 |
| Stop/保存失败 | 留在 Error，保留具体错误、重试/取消；不根据旧的成功标志继续退出 |

读取与诊断继续可用。离开模态期间隔离 Game 输入，取消 UI capture，恢复时 prime 输入，
避免关闭弹窗的鼠标抬起或按键成为游戏点击；不通过 neutral Step 模拟点击。
未确认 Stop 前保持既有模拟运行，取消离开不会自动重启/重放；这一点在 UI 中明确。

### 3.3 防止确认期间 Agent 又改动

在 `ProjectSession` 引入 owner-thread、RAII 的生命周期操作令牌，控制器进入 Review 前取得。
它不是 CommandBus transaction，不产生历史，不更改 Scene dirty；不能从 MCP 参数获得。
普通 Execute/Undo/Redo、Save/Export、Settings Save、Runtime Control、Transaction Begin
在令牌活动时返回明确 busy。控制器持有令牌，通过受保护入口执行经确认的 Stop/Save/回滚。
令牌内部仍检查 Runtime、transaction、recovery，不允许“一把 token 跳过所有校验”。

已活动事务允许原 owner Finish（Commit/Rollback）、超时及断连清理；发生变化后重新读取状态，
使旧选择失效。控制器主动回滚必须验证仍是确认时的 transaction UUID/owner，失败检查
`RecoveryRequired()`，不依赖现有 void Cancel 方法表示成功。

MCP host 对生命周期 busy 的写请求在 owner-thread 分类/权限检查后、路由和 `AbortOwnedRequest`
之前拒绝；不能因为弹窗
造成的一次拒绝，误触发 Agent 事务回滚。此前已授权的真实命令失败仍保留原补偿规则。
重复输入不抢占已有 intent；Cancel 释放令牌，输入与后续请求恢复，不清空 dirty/history。

### 3.4 字段草稿、设置草稿和清理

离开请求先按明确规则处理正在编辑的字段：有效值按当前提交规则形成一次命令，再检查 dirty；
无效值留在输入错误状态，用户修正或明确取消草稿，不能静默丢弃。Move 临时预览取消而不提交。
按 X 与字段失焦同帧时，次序必须通过自动测试固定，不能依赖 ImGui 绘制顺序巧合。

`ProjectSettingsPanel` 目前只有分散的字符数组和 m_Draft。提取可测试的 draft model，
比较规范化后的全部字段；字符数组改动也计入草稿。保存成功重设基线，失败保留，切项目重绑定。
草稿窗口关闭采用保存/放弃/取消；本地偏好写失败仅告知，不冒充 Scene 保存失败。

ExitAccepted 前完成事务处置和显式 Runtime Stop；之后停止 MCP dispatcher/worker，
再销毁面板/草稿引用、CommandBus、Scene、AssetService，最后 Renderer/Window。
Paused/Faulted 也按 `HasRuntime()` 处理。MCP Stop 的断连清理继续幂等，在 owner thread 执行；
不在析构函数内弹框或保存。明确放弃 recovery 时允许销毁会话，但不恢复作者态写权限。

## 4. B 包：Duplicate 与资源工作流（原 R3/R4/R5）

### 4.1 DuplicateEntityCommand

入口为 `EditorActions::DuplicateEntity(UUID)` 和 `scene.duplicate_entity`，均经
ProjectSession ExecuteAuthoring；MCP 分类为 SceneWrite，支持现有 transaction owner/token。
Ctrl+D 仅在作者态且无文本/Game 焦点时生效。返回新根 UUID，Human 选择新根。

实现从当前 Scene 捕获有界子树，复用/提取 Prefab 的 UUID 重映射与快照验证辅助函数。
不先导出 Prefab 文件再读回；不拷贝 Scene/Registry，不改变资产身份，不引入 EntityReference。
上限沿用 1024 实体、64 层，并遵守 CommandBus 的保守 Undo 字节预算。
重映射辅助必须显式区分两种调用：Prefab 是封闭根，Duplicate 保留根的外部 parent；
只重映射子树内部 parent，拒绝除此之外的外部层级关系，不能对外部 parent 直接调用映射表 at。

- 根实体副本仍为根，根排序保持 UUID 顺序；非根副本位于原对象后、同一 parent 下。
- local 字段、后代 sibling order、组件与资源引用保持；根显示名用 `原名 Copy`，
  后代名保持。身份由 UUID 保证，不承诺名称全局唯一，也不偷偷位移副本。
- 新 UUID 在首次准备时生成；Redo 恢复同一不可变快照，不重读源对象/磁盘。
- 多 primary camera、第二个/嵌套 Canvas 等违反现有约束时整体拒绝；不暗中取消 primary。
- Restore 失败补偿，补偿失败使用现有 recovery 契约；一次成功对应一条历史和完整活动影响集合。

### 4.2 统一资源槽和 Prefab 名称

保留现有类型选择与 None，补搜索、Locate、拖入；菜单选择与拖入共用同一验证和 SetProperty。
六类槽分别验收 SpriteRenderer.texture、Image.texture、Text.font、Animator.clip、
AudioSource.clip、LuaScript.script。丢失 UUID 不自动清空，错误类型/取消不改原值。
Locate 只改变资源面板筛选/选择，不改变实体选择；拖拽 payload 用资产 UUID 和项目代数，
不使用资源数组地址。Runtime/事务/recovery 拒绝仍由后端执行。

`ProjectSession::ExportPrefab` 增加可选显示名称参数，旧调用省略时保留 UUID 文件名兼容性。
Human 弹框默认实体名，预览 `Prefabs/<合法名称>-<UUID>.prefab`；MCP export 同步增加可选 name。
名称限定单个 UTF-8 文件名片段，拒绝分隔符、路径跳转、控制字符、Windows 保留名/尾随点空格，
限定长度；不静默将两个非法名称变成同一个名字。新 UUID 和 create-only 文件提交防覆盖。
保存 Registry 成功才发布内存 Registry；失败删除本次新文件并报告清理失败，维持现有崩溃孤儿边界。
不修改 AssetMetadata 格式、不提供重命名旧资产/关联 Prefab/Override。成功后定位新资源。

## 5. C 包：单对象 Move Gizmo（原 R5）

采用 2D 世界 X/Y 轴与平面手柄，旋转/缩放仍用 Inspector。Q/W 切选择/移动；F 保留聚焦。
只有 Scene View 的已选世界 Transform 可操作，UIRect/Canvas 禁用并解释需使用布局属性。
输入优先级：模态 → 文本/资源拖拽 → 已捕获手柄 → Scene 拾取/导航 → Game 输入。

建议 `EditorTransformDrag` 为值状态，记录项目代数、Scene revision、authoring generation、
entity UUID、parent UUID、原始 local position、起点世界位置、父链矩阵和视口映射。
拖动期间切视图、缩放/相机移动、resize/DPI 改变、失焦、Esc、实体删除、父链改变或运行开始
均取消；释放无位移不提交。只支持一个指针捕获和一个目标，不加入多选。

计算使用完整父链二维仿射矩阵：

```text
worldTarget = worldStart + constrainedWorldDelta
localTarget = inverse(parentWorldMatrix) * worldTarget
```

屏幕点先从 ImGui 显示矩形映射到 render-target 像素，再用 EditorCamera::ScreenToWorld，
Y 轴转换只做一次。父矩阵必须由当前 local 链计算，不能依赖可能尚未渲染更新的 world 缓存。
对旋转/非均匀缩放组合使用完整矩阵；近奇异、非有限结果拒绝。Core 若补逆变换，只增加通用
有失败返回的二维仿射数学函数，不依赖 Scene。Ctrl 将受约束的世界位移吸附到当前显示网格的
明确间距，UI 显示该间距；未约束轴保持不变，释放 Ctrl 回连续位移。

SceneRenderRequest 增加默认空的单根临时 local-position override（UUID + Vector2）。
提取现有层级姿态计算，正常渲染保持当前语义；有预览时生成局部 scratch pose 表，子树跟随。
渲染、选中框和手柄共用预览结果，预览路径不写 Transform local/world 缓存、不进入 Game View、
序列化、克隆或 MCP 资源。保留当前 Sprite rotation/scale 表达，不顺带改变引擎剪切渲染语义。

新增 session 内 authoring generation：每次成功作者态变更、Undo/Redo、事务中实际变更、
回滚/恢复导致状态改变时推进；仅 Commit 分组不伪装为 Scene replacement。Runtime 成功启动也推进此失效标记，
覆盖同一次 Pump 中 Play→Stop；它不更改作者态 dirty/history。现有 Scene revision
继续用于对象图替换。拖动不锁住 Agent；任何作者态 generation 变化都取消本次预览。
松手通过 ProjectSession 的条件提交入口原子检查 revision/generation，再执行一个
SetPropertyCommand；检查和提交在同一 owner-thread 调用内完成。失败清预览并保留错误。

## 6. D 包：偏好、属性与诊断收口（原 R2/R3/R7）

- `EditorPreferences` 使用版本化本地文件，路径由 Platform 用户数据目录接口提供，
  Windows 实现在 Platform 中。不得存进 project.json 或项目仓库。
- 保存 userScale、语言、标准/专注/调试布局、分栏比例、面板展开、最近项目（最多 10），
  每项目/Scene 的相机取景（有界，建议最多 32）。不保存 selection ECS handle、Runtime 或 GPU 状态。
- 读取大小有界（建议 64 KiB）；缺失用默认，损坏提示并回退，尺寸/缩放钳制；
  DPI 是当前设备输入，不能把旧设备系统倍率存成用户倍率再乘一次。
- 拖动结束/显式设置改变后节流写本地文件，退出时 flush；IO 失败不阻塞场景保存或正常退出。
  不承诺多个 Editor 进程合并偏好，采用最后成功写入者优先。
- 核心标签 zh-CN/en-US 集中映射；Reflection serializedName、MCP key、Scene v1 不翻译。
  字体选择/回退与中文路径实际测试；不擅自把 Windows 系统字体打入包。
- Inspector 数值/文本采用草稿，Enter/有效离焦一次提交，Esc 取消；轴标/单位保持真实弧度。
  键盘快捷键不能跨文本字段 Undo/Delete。已有资源选择不改成另一套命令。
- Console 补真实时间/分类、等级计数、文本搜索及选中详情；全部来自现有 LogStore，
  不另建日志缓存。Profiler 保持 CPU 名称，未采样为空；Activity 定位按 UUID，已删除对象解释原因。
- Faulted 横幅提供错误定位和 Stop；清理成功才恢复作者态。Game 按战斗阶段设置已有
  Button.enabled/提示，规则仍由 Combat.lua 验证，无效动作无副作用；恢复/热重载路径一并回归。

原生显示验收沿用原设计的 1080p/1440p/4K 与 100/150/200% 可用组合，明确工具截图逻辑
尺寸与屏幕像素；覆盖多屏切换、模态按钮可达、中文无缺字、手柄坐标和 Game 输入边界。

## 7. E 包：场景与项目生命周期（原 R6）

### 7.1 单活动 Scene 的数据模型与 API

保留一个活动 Scene。建议在 ProjectSession 增加以下受保护操作，不纳入 Undo/事务：

| 建议入口 | 成功语义 |
| --- | --- |
| PrepareNewScene(relativePath) | 路径合法且目标不存在；构建空 Scene 候选，无磁盘写入 |
| PrepareOpenScene(relativePath) | 使用 active ReflectionRegistry 完整加载并验证候选 |
| CommitPreparedScene(candidate, leaveToken) | 最终重查状态后替换；清旧历史，增加 revision/generation |
| SaveSceneAs(relativePath, writeMode) | 写成功才更新当前路径；保留实体 UUID、选择和历史，dirty=false |

候选保存源 session/revision/generation，过期拒绝；必须在离开控制器保护下提交，
不能向任意调用者暴露 `ignoreDirty=true`。无 token 的普通 Open/New 遇 dirty 拒绝，
Human 在控制器明确保存/放弃后获准；MCP 首期必须显式 scene.save 后切换，不能弹 Human 对话框。
MCP 调用 ProjectSession 的 OpenScene/NewScene 便捷入口，在同一 owner-thread 调用内完成
干净状态检查、内部令牌获取、Prepare/Commit；这些入口不接收跳过 dirty 的参数。

New Scene 先让用户选择项目内的 `.scene` 路径，再建立内存文档：path 是预定路径，
`hasSavedFile=false`、dirty=true。不引入空字符串路径去破坏现有资源字段约定。
空场景合法，Game 预览显示“添加 Camera”；可通过现有 Create/Add Component 操作制作。
新文档首次 Save 使用 create-only，若另一个文件占用了路径则报错并要求另存。
新文档没有磁盘版本，Recovery 的明确 discard 重新构造空 Scene，不能调用 Load 不存在的文件。

Open/New 成功清选择/拖动和面板草稿、清旧命令历史，重置相机首次取景；成功 Open 为 clean，
New 为 dirty。SaveAs 只改变作者态文档路径和保存状态，不更改 `project.json.defaultScene`，
不清 Undo；其后 Undo 仍按既有保守 dirty 语义置脏，不引入保存点追踪。
项目设置 defaultScene/path 改动继续按现有“重开后生效”约定，普通 Open Scene 不顺带保存设置。

### 7.2 准备后替换与文件失败

打开候选场景/项目优先在旧内容仍有效时做完路径、解析、schema、必要依赖验证；失败保留
旧对象图、路径、历史、dirty、选择、MCP 绑定。仅预检成功后才询问是否离开旧文档。
依赖文件在预检后变化的情况，在最终提交前复查需要的身份与约束；不承诺跨进程项目锁。

同 Scene 替换顺序：停止运行 → 清所有旧视图借用 → 清命令（命令必须先于旧 Scene 销毁）→
无失败的指针交换 → 更新路径/flags/revision → 更新面板与 MCP。必要分配/验证在交换前完成。
旧 Renderer/AssetRegistry/Reflection 在同项目切 Scene 时保持；不建立第二个 registry singleton。

所有场景路径经过 `ResolveProjectPath`，允许项目内 `.scene`，拒绝越界、目录、错误扩展名，
新路径按已存在父目录解析链接。缺失目录须显示明确创建意图，失败只清本操作的新临时文件。
SaveAs 对已有目标要求显式覆盖选择；MCP 默认拒绝覆盖，必须传显式 overwrite。
FileSystem 补 create-only 原子提交，Windows 平台后端不能设置 REPLACE_EXISTING；
对已确认覆盖保持现有 replace 语义。验证失败/写失败/rename 失败保持原文件和活动路径。
不把预先 exists 检查当作防覆盖保证；不承诺抵抗恶意外部进程并发替换项目链接或写同一文件。

### 7.3 MCP 绑定与排队请求

新增 `scene.new`、`scene.open` 分类 SceneWrite；它们不加入 transaction，dirty/Runtime/
recovery/生命周期 busy 时明确拒绝。`scene.save_as` 为 SceneSave；`scene.duplicate_entity`
仍是可撤销 SceneWrite。参数使用项目相对路径/UUID；全走现有分发与 permission seam。
生命周期工具的 transaction 参数一律拒绝，不通过通用“失败即 AbortOwnedRequest”路径偷偷回滚。

在 host 中把 `EnsureSceneBindingsCurrent` 放到**每次 owner-thread 请求路由之前**；
不能在正在执行的 handler 内销毁其所属 ToolRegistry。切换 handler 返回后，下一条请求
先刷新绑定再路由。重建失败则 fail closed，绝不调用旧 Scene 指针；新注册集先准备后交换。

host 维护原子的 binding epoch，Scene/project 切换时推进。IO worker 只在排队时读取 epoch，
闭包执行前在 owner thread 校验；切换前已排队的旧请求返回 context changed，要求重新读取上下文。
这些拒绝不回滚新会话事务。补 scene/current 和 project/info 的 epoch/revision 元数据；
新工具支持 expectedRevision，现有工具不强制新增必填字段，保持旧客户端兼容。
已延迟发送且没有前置条件的旧客户端请求按实际执行时当前场景解释；epoch 不被描述成完整并发控制。

### 7.4 打开项目、欢迎页与 MCP host

显式 `--project`、旧 positional 参数保留，加载错误仍清晰返回；生产 `--mcp-stdio`
不进入交互欢迎页，不改 stdout 契约。没有项目参数的 Human 启动显示欢迎页；需区分
“参数省略”和解析器生成的默认路径，不能拿 SandboxProject 默认值误认为显式选择。
无参数 MCP 保留旧 SandboxProject 默认路径兼容行为。

Main 目前在构造 Application 前加载项目设置。重构为可启动空 Editor shell：无项目 Human
使用 Editor 默认显示设置；已有显式项目继续原加载方式。shell 不运行需要 project 的面板。
打开随包示例先复制到用户选定的可写新目录；复制/验证失败不添加最近项目、不覆盖既有目录。
只清理由本次操作创建并确认归属的副本文件。关闭窗口不保存安装目录中的原示例。

项目切换先准备新的 ProjectSession 和依赖面板，旧会话仍完整。McpEditorHost 当前引用必须
改为可受控重绑定的借用指针；由 owner-thread `RebindProject` 原子切换已准备的 capability 集
和 session 指针，推进 epoch，不 Stop/重新初始化已有 stdio transport。旧项目仍存活到所有
同步 handler 返回、旧 binding 清理、旧面板/命令/runtime 释放完成。新 host 不维护第二套协议。
事务/recovery 必须先按 A 包处置，不能在 rebind 时隐式转移 transaction owner/history。

项目切换不热建 Window/GraphicsContext；当前 vsync/targetFPS 保持至重启，提示与原设置
生效契约一致；逻辑分辨率/input 来自新 session。无项目 shell 不启动 MCP，首次明确项目
就绪后才按启动模式创建 host。项目切换不暴露新的任意文件系统 MCP 工具。

## 8. F 包：Release 候选与发布出口（原 R8）

补 `windows-msvc-release`、`windows-msvc-release-tests` configure/build/test presets，
建议 CI 同时跑 Debug/Release tests；现有 Debug 回归不替换。新增预设完成前不声称相关命令可用。
加入 CMake install/staging 规则：Editor、Sandbox runtime runner、项目副本模板、
shader/字体等实际运行资源、入门说明、已知限制、版本与第三方 notices，排除 Tests fixture、out/ 和开发机路径。
SDL 静态链接不表示全部 runtime dependency 已消失：实际检查 MSVC runtime 和资源路径，
干净 Windows 环境验证；不添加另一个生产 MCP executable。

建议用 CPack ZIP 生成可复现入口，manifest 记录版本、完整 Git SHA、构建配置、工具链、
依赖固定身份和文件校验和。“可复现入口”不等于已证明二进制逐字节可复现。
CI 使用 `cmake --install ... --prefix <staging>` 后打包；最终具体路径在实现的 presets 中固定。
不靠构建后复制到源码目录打包。包内示例不可直接当用户保存目标。

候选验证覆盖原生 Editor、Sandbox、modern/legacy 生产 stdio、音频设备及人工试听、
真实目标设备/GPU/Present 的完整帧观测。CPU instrumentation 与 wall-frame/GPU 指标分别
记录，若无 GPU 计时来源则明确未测；不能用 FakeRenderDevice 的 1–2 ms CPU 结果承诺 60 FPS。
记录设备、驱动、分辨率、vsync、暖机/采样区间、median/p95/p99 与限制，不先编造性能阈值。

候选阶段统一 CMake、MCP、About 与包版本。建议最终版本 `0.10.0`，Preview 定位明确写在
发布材料；是否使用预发布 Tag 命名在发布时确定。项目开源许可仍须 owner 决策，第三方/字体/
示例素材分发材料须核对；设计与本地候选构建可继续，不擅自选择项目 License 或自动发布。
Tag/Release 仅在候选提交 CI、原生 PM 和分发出口全部通过且有发布授权时创建。

## 9. 验收与完成定义

每个行为包先写失败测试，再实现，跑最窄用例和两个 Debug configure/build、全量 CTest；
新增 Release 预设后同时跑 Release。共用测试 fixture 可注入写/rename/rollback 失败，
不能只依赖“设置目录只读”这种在 Windows 上不稳定的注入方式。

自动层重点：关闭拒绝与幂等清理、busy 不误回滚、保存失败不丢状态、完整父矩阵移动、
预览不进入 MCP/保存、Duplicate UUID/历史、场景切换同 Pump 多请求、旧请求拒绝、项目重绑定。
原生层重点：X/Alt+F4/菜单、字段编辑中关闭、settings 草稿、拖动失焦与 DPI、资源六类赋值、
新建/打开/另存/重开、胜负/暂停/热重载/Faulted、干净机器与音质。

保留原 UX 的首次用户验收：5 位未使用 Janus 的试用者，至少 4/5 仅靠随包说明完成制作链，
记录耗时和求助；所有数据保护用例必须通过。未组织试用就记录待验收，不能由内部熟练操作替代。
PM-01 任一数据丢失回归、改错对象、旧 Scene 指针访问、输入泄漏、关键按钮不可达均阻断发布。

本设计不将当前 417 项测试当作新增行为的证明。设计文档只检查路径链接、围栏、表格和
`git diff --check`；实现时另建按提交 SHA 记录的验证文档。
