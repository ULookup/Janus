# 首个 Release 前的编辑器体验优化设计

日期：2026-09-07。基线：`7ecdfb8`；依据：[PM 实机验收](../../verification/2026-09-07-pm-editor-acceptance.md)、[产品进度](../../project-status.md)。
状态：产品设计提案，尚未实现；优先级与出口是本方案的建议，不是已经通过的验收。

## 1. 定位与目标

建议首个公开包定位为 **Janus v0.10 Windows Preview**：用户能打开项目、理解场景、
使用已有资源制作一个小场景、运行调试并可靠保存。不将首个 Release 等同于路线图 v1.0。
本轮设计针对 Editor 的 Human 制作体验，保留 Agent-native 的共享命令与可观察性。

一句话目标：**第一次打开能找到内容，常用操作不用猜，编辑结果能保存且不会意外丢失。**

首版完成五条路径：打开项目 → 定位对象；创建/复制 → 移动/改属性；找资源 → 赋值/Prefab；
运行 → 暂停/诊断 → 返回编辑；保存 → 切场景/关闭 → 重开。
新建完整项目向导、通用资产导入管线、完整游戏打包向导仍是 PRD 待办；本版提供明确的
示例与资源准备说明，不宣称可以从任意外部素材完成全流程游戏生产。

## 2. 成熟产品参考与 Janus 取舍

以下依据官方界面文档，访问日期为 2026-09-07。借鉴的是信息组织与交互原则；具体栏目、
尺寸、快捷键和发布优先级均是 Janus 的设计决定，不是竞品规格或现成能力。

| 参考 | 官方界面事实 | Janus 采用方式 |
| --- | --- | --- |
| [Unity 界面](https://docs.unity.cn/Manual/UsingTheEditor.html) | Hierarchy、Scene/Game、Project、Inspector 分工，工具栏包含运行控制与布局入口 | 固定默认认知位置；Scene 与 Game 明确分开；层级选择联动 Inspector |
| [Godot 界面](https://docs.godotengine.org/en/stable/getting_started/introduction/first_look_at_the_editor.html) | Scene/FileSystem docks、中央工作区、可展开的底部诊断面板及专注模式 | 资源与诊断按需展开；低频设置移到菜单；保留中央画布空间 |
| [Cocos Creator 3.8 界面](https://docs.cocos.com/creator/3.8/manual/en/editor/) | 层级与 Scene 同步，Assets 目录呈现，Inspector 按当前选择显示属性 | 适合 2D 的对象—资源—属性流程；组件字段使用合适控件和明确单位 |
| [Unreal Editor 界面](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-editor-interface) | 全局工具栏与视口工具栏分工，Content Drawer、Details 和保存状态入口 | 运行控制独立分组；视图工具留在画布；资源可折叠、保存状态可见 |

首版采用“可调分栏 + 固定栏目 + 三个预设”，不以任意拖拽 docking、多窗口、3D 工具栏、
Timeline 或内置代码 IDE 为前置条件。这样能直接解决目前固定小面板问题，并控制验证范围。

## 3. 默认栏目结构

```text
Janus · Robot Card Arena · Integrated.scene *
文件   编辑   场景   项目   视图   帮助
[保存] [撤销] [重做]        [运行] [暂停] [单步] [停止]       编辑中 | 标准布局
┌ 场景层级 ─────────┬ 场景 Scene | 游戏 Game ───────────┬ 属性 Inspector ──┐
│ 搜索对象   + 创建 │ 选择  移动 | 聚焦  全景 | 网格    │ Hero             │
│ Integrated       │                                │ Transform        │
│  Camera          │       可取景、可拾取的 2D 画布    │ SpriteRenderer   │
│  Canvas          │                                │ Animator         │
│  Hero  ← 选中    │       选中框与移动手柄             │ clip [RobotIdle] │
│  Enemy           │                                │ [+ 添加组件]     │
├──────────────────┴────────────────────────────────┤                  │
│ 资源 Assets | 控制台 Console | 性能 Profiler | Agent 活动 │                  │
│ 目录 / 搜索 / 类型             资源列表、缩略图或诊断详情 │                  │
└───────────────────────────────────────────────────┴──────────────────┘
已保存 / 未保存 / 保存失败       错误 0 · 警告 1          Agent 状态
```

Inspector 贯穿内容区高度，底部工作区只占层级与画布下方，避免属性被资源列表挤压。
“场景”是当前对象结构，“资源”是项目中可复用的内容；不再用 Project Settings 作为默认底部首项。

| 栏目 | 固定职责 | 主操作与默认状态 |
| --- | --- | --- |
| 顶部菜单 | 文件生命周期、低频设置、帮助 | 完整文字；没有实现的功能不展示伪可点击入口 |
| 主工具栏 | 保存/历史；运行控制；工作区状态 | 各组位置稳定，Pause 变 Resume 也不导致其他按钮位移 |
| 场景层级 | 搜索、选择、组织当前 Scene 实体 | 根场景名、组件类型图标、展开树；右键与可见“创建”按钮 |
| 中央视图 | Scene 制作与 Game 预览 | 初次加载对有效场景取景；工具只显示当前视图支持的操作 |
| 属性 | 当前实体的已有组件，或资源元数据 | 名称在顶部；字段分组；唯一“添加组件”入口；UUID 放在可展开详情 |
| 资源 | 注册资源的查找、选择、赋值、Prefab 实例化 | 目录、名称搜索、全部类型筛选；操作栏固定，不在长列表末端 |
| 控制台 | 错误/警告/信息与详情 | 带数量、等级/文本过滤，选择条目查看详情；错误入口不强制抢焦点 |
| 性能 | CPU 阶段与渲染提交计数 | 明确 CPU 标签；不伪装成 GPU/FPS 保证 |
| Agent 活动 | 操作记录、事务/恢复状态 | 常规折叠，状态栏有入口；不添加没有后端支持的聊天框 |
| 项目设置窗口 | 当前项目配置 | 项目菜单打开，分类为基本、路径、显示、输入；保留生效时机提示 |
| 编辑器偏好窗口 | 字体/缩放/布局/语言 | 与 project.json 分离，不改变 Scene dirty 或命令历史 |

### 菜单与快捷键

| 菜单 | 首版目标项 |
| --- | --- |
| 文件 | 打开项目、最近项目；新建场景、打开场景、保存、场景另存为；退出 |
| 编辑 | 撤销、重做；编辑器偏好 |
| 场景 | 创建实体、复制所选、重命名、删除、导出 Prefab |
| 项目 | 项目设置、在文件管理器中打开项目目录 |
| 视图 | 层级/属性/底部工作区显示；标准/专注/调试布局；恢复默认布局 |
| 帮助 | 5 分钟入门、快捷键、格式与限制、版本信息 |

新建/打开/另存 Scene、打开项目 UI、Duplicate 是新增工作，不是已有能力换按钮，见实施计划。
支持一个活动 Scene；不引入多文档并行编辑。项目切换失败保留当前会话。

快捷键建议：Ctrl+S 保存；Ctrl+Shift+S 另存；Ctrl+Z / Ctrl+Y 撤销/重做；Ctrl+D 复制；
F2 重命名；Delete 删除；F 聚焦所选；Home 全景；Q 选择；W 移动；F5 运行/停止；
F6 暂停/继续；F7 单步；Esc 取消当前拖拽/弹层。首版旋转/缩放先通过属性数值完成。
快捷键必须遵守焦点：输入框编辑优先；Delete 不跨字段删实体；Game 获取输入时不接收
Q/W 等作者态操作。全局运行键被 Editor 消费，不再进入游戏 Action。所有快捷键都有菜单入口。

## 4. 尺寸、视觉与布局规则

采用中性深灰、清晰分隔线和单一蓝色选择态；成功/警告/错误配文字，不只依赖颜色。
首版把“舒适”作为默认密度，紧凑密度可选；不做大面积装饰卡片或过大的空白标题。
界面文案集中管理，方案示意采用中文主标签与英文术语；首版核心 UI 支持 zh-CN / en-US。
组件/属性内部名称、Scene v1 字段及 MCP 名称不随语言变化。

建议基准（均为逻辑单位，非截图像素，实施时以实机校准）：

- 主字体 15–16，辅助文字不低于 13；常用行高 28–30，按钮高度 28–32，工具图标 16–18。
- 默认左栏 240、右栏 320、中央至少 480；分隔条可拖拽，命中宽度至少 6。
- 底部默认 240，可展开至内容高度约 50%，也可折叠到标签栏；原来 230 上限取消。
- 缩放采用“系统 DPI 自动 × 用户缩放倍率”，提供 Auto 与 100/125/150/175/200%；
  文字、间距、图标、命中区域和视口坐标转换一起验证，防止双重 DPI 缩放。
- 逻辑宽度不足 1100 时使用紧凑布局：左右栏切为可开关侧栏、底部默认折叠；
  不缩小正文硬塞。关键模态窗口适配当前可用区域，按钮始终可见。
- 标准：完整制作；专注：画布最大化、侧栏可召回；调试：Game + 扩展底部诊断。
  切布局不改 Scene、选择或运行状态；恢复默认随时可用。
- 布局、面板展开、视图相机与最近项目写入本地用户配置。缺失/损坏回退默认；
  更换显示器后边界钳制，不允许面板恢复到屏幕之外。
- 中文路径/名称必须可读；字体 fallback 和字体分发许可纳入发布验证，不默认系统字体覆盖全部字形。

## 5. 核心流程细化

### 5.1 安全打开、保存、切换和退出（PM-01）

启动无路径时显示轻量欢迎页：打开已有项目、最近项目、打开随包示例；失效最近项目显示原因。
随包示例首次使用复制到用户可写目录；安装目录只读不能导致保存失败或污染原包。
保留 `--project` 与生产 MCP 启动，交互式欢迎页不能卡住明确指定项目的自动启动。

当前文档名旁显示 `*`，状态栏明确“有未保存更改”；Save 成功才清除。
X、Alt+F4、菜单退出、打开另一项目/场景、新建场景统一经过离开检查：

1. 先结束或取消当前字段/拖拽交互；弹层优先获得焦点。
2. Runtime 存在时显示“停止运行并继续 / 取消”；经既有 Stop 完成清理，不能保存 RuntimeScene。
3. 有未保存的作者态 Scene 时显示“保存并继续 / 不保存并继续 / 取消”；默认焦点为取消，Esc 取消。
4. 保存错误显示原因与重试，保留当前会话及 dirty；没有成功前不得执行退出/替换。
5. 项目设置窗口有未应用的草稿时独立提示应用/放弃/取消，不能用 Scene Save 冒充已保存设置。

Agent 事务/恢复状态继续沿用 owner/token 与恢复策略；不在退出弹窗中自动提交 Agent 事务。
遇活动事务阻止项目/Scene 切换并说明原因；应用退出的安全清理策略须在专项设计中覆盖补偿失败。
“不保存”只放弃当前 Scene 的未落盘改动，不回滚此前独立保存的 Prefab 或项目设置。

### 5.2 找到对象并移动（PM-02）

初次打开对可见世界内容进行 Fit All，显示相机边界；背景等超大装饰不可让主体缩成像素。
保存过取景的项目优先恢复取景，始终提供 F / Home。无可渲染内容显示创建/聚焦提示，不显示伪故障。
层级点击与画布点击共用同一 UUID 选择；双击层级或 F 聚焦；场景显示选中边框。

首版提供 2D 平移手柄：X/Y 轴与平面拖动，Ctrl 临时网格吸附，拖动提示位移。
预览不直接写 ECS；鼠标释放只提交一次共享 SetProperty 命令，Esc/失焦取消预览。
父子层级按当前局部/世界变换契约换算；无法逆变换时拒绝并解释，不能静默改变局部值。
UIRect 使用布局矩形选择与属性编辑，不让世界 Transform 手柄错误移动 UI；UI 拖拽排入后续。

### 5.3 属性面板与资源赋值（PM-05）

顶部实体名可直接重命名。只显示已有组件；把现有整列 Add 按钮收为底部“添加组件”，
弹出可搜索列表；已有组件不重复添加，移除等次要操作进入组件菜单。
数值字段显示轴名、单位、有效范围；即时本地校验；Enter/离焦提交一个命令，Esc 撤销输入草稿。
Transform 旋转若显示角度，明确单位并在边界转换，内部仍为弧度。

所有 AssetReference 使用统一资源槽：`类型图标 + 可读名称 + 选择 + 定位 + 清空`。
资源 UUID 和路径在详情可复制，不能作为唯一主标签。资源选择器可搜索、按允许类型过滤；
明确报错“需要 AnimationClip，当前为 Texture”，失败不改值。
支持从资源列表拖入同类槽；拖拽是快捷方式，点击选择可完成同样操作。
覆盖 SpriteRenderer.texture、Image.texture、Text.font、Animator.clip、AudioSource.clip、LuaScript。
清空沿用既有 nil 语义，若运行需要非空引用，显示状态提示而非偷偷填默认资源。

运行时属性面板注明“编辑场景 · 只读，停止后可编辑”，不让 Hero 的作者态位置看起来像实时物理值。
首版不增加可写 Runtime Inspector；实时状态继续放在现有诊断/快照路径。

### 5.4 资源与 Prefab（PM-04 / PM-06）

资源浏览器按 registry.relativePath 构建目录视图，支持名称/路径搜索、七种现有类型筛选、
列表与可行的 Texture/Prefab 图标预览。Scene 文件属于文件入口，不假装已注册为 AssetType。
单击选择时 Inspector 显示资源详情，层级中的上次实体选择仍可返回；资源槽选择器不改变实体选择。

Prefab 选中后，固定顶部操作栏显示“实例化”；默认放到 Scene 根，不隐式嵌到当前选中对象。
选中后提示“展开为普通实体，无源文件联动”；创建后定位新根；一次 Undo 移除整棵实例。
导出弹窗请求可读名称，展示目标路径；使用合法化名称与 UUID 防碰撞后缀生成新文件，
不覆盖现有 Prefab、不更改原 UUID 身份；取消不产生文件。继续遵守文件/registry 保存补偿。
成功后定位新资源。该切片不提供关联 Prefab 的 Apply/Revert 假入口。

外部导入仍未具备时，资源空状态直接链接“支持格式与注册步骤”；不摆设无功能的 Import 按钮。
另存场景路径仅限项目内，覆盖已有文件需确认；当前场景身份只在写成功后更新。

### 5.5 运行、诊断与 Agent 可见性

工具栏运行/暂停/单步/停止固定占位，状态完整显示 Stopped / Playing / Paused / Faulted。
Play 切 Game；Stop 恢复运行前用户选中的视图与取景，不强制跳回 Scene。
Paused/故障态有明确横幅；暂停 Step 仍是 1/60 中性输入，不回放点击。
Game 标出逻辑分辨率与输入焦点；菜单、资源拖动、黑边、弹层输入不得落入游戏。

Console 保留等级/文本过滤、折叠重复消息与详情；Faulted 出现“查看错误”和 Stop，
不自动清空证据或恢复运行。Profiler 使用现有记录能力；未采样显示未采样，不填虚构耗时。
Agent 状态只显示宿主真实提供的信息：例如作者态是否被事务占用；不能仅凭 MCP 初始化
推断用户连接或权限等级。活动记录可定位仍存在的实体；删除实体显示不可定位原因。

## 6. 范围与工程边界

首版必做：PM-01～PM-06 对应体验、布局/DPI、资源赋值、场景基本生命周期、Duplicate、
选择/取景/平移、故障提示、可复现 Release 包。PM-07 与主线同时收口，属于 Game 示例逻辑。
完整 docking、多屏浮窗、通用 Import/Reimport、动画时间线、状态机、代码 IDE、资产商店、
多选/批量编辑、关联 Prefab、Runtime 改动回写均不在本优化包内；原 PRD 待办继续保留。

沿用 Dear ImGui；当前固定 `v1.92.9b`，本方案默认实现受控 split 布局，不依赖未核实的 docking API。
所有 Human 变更经 EditorActions → ProjectSession → CommandBus；不新增 UI 直写 ECS 路径。
布局/语言/取景是 Editor 本地状态；场景设置、Scene Save 与导出仍有各自持久化边界。

需要专项设计的三个边界：可取消关闭请求（Platform/Application seam，不让 Core 依赖 Editor）；
新建/切换/另存 Scene（ProjectSession 生命周期和 MCP scene revision 刷新）；拖拽临时预览
（不改变 authoring/dirty，在受保护提交前不产生命令）。方案通过这些小切片落地，不做全引擎重构。

## 7. 发布验收目标

以下为待测目标，未宣称达成。5 位未接触 Janus 的试用者，每人只获得随包入门说明，
记录任务成功率、耗时、中断位置与求助次数；至少 4/5 独立完成整条制作任务、无数据丢失。

| 任务 | 成功条件 / 目标 |
| --- | --- |
| 首次打开示例 | 60 秒内找到 Hero，能说明层级/场景/属性/资源分别做什么 |
| 创建并配置对象 | 5 分钟内创建 Sprite、选择注册 Texture、移动到指定区域、命名并保存，不编辑 JSON |
| 动画/UI 资源赋值 | 2 分钟内给已有 Animator 与 Image 选择正确资源；错误类型被拒绝，Undo/Redo 正常 |
| Prefab 流程 | 3 分钟内命名导出、查找、实例化、撤销并重做；理解实例不关联源文件 |
