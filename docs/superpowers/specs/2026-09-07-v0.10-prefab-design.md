# v0.10 / 10-09 Prefab Foundation

日期：2026-09-07。基线 main/origin/main `b9b990b`，已包含 #89/#90/#91。
旧文档关于依赖分支尚未集成的状态已经过时；本设计依照路线图的 Prefab Foundation，
技术架构将 Prefab Override 留作未来扩展，两者范围一致。

## 契约

- Prefab 是可复用实体子树模板。`janus.prefab` version 1 包含 `root` 和嵌入的
  `scene`（完整 Scene v1 文档）。只允许一个根、闭合层级、最多 1024 实体、64 层、
  1 MiB UTF-8 JSON；拒绝未知顶层字段、重复键、过深 JSON、断链、循环和多根。
- 使用调用者的 active ReflectionRegistry，以及 Scene v1 序列化/校验。子树捕获与
  恢复复用 DeleteEntityCommand 的快照设施，不建立第二套组件编解码。
- 每次实例化为所有实体生成新 UUID，重映射内部 parent，保留兄弟顺序和局部字段。
  当前 PropertyType 没有 EntityReference，现有组件仅有 AssetReference；资产 UUID
  和普通字符串原样保存。未来实体引用类型必须显式增加重映射，禁止猜测 UUID 字符串。
- 首版展开为普通 Scene 实体，无运行时 Prefab 组件、来源连接、嵌套模板、override、
  apply/revert 或热传播。实例作为根插入，可用现有 Reparent 命令调整父节点。
- InstantiatePrefabCommand 先解析验证并保留不可变快照，一次 Undo 删除整个实例；
  Redo 恢复同一 UUID 和内容，不重新读取可能已经改变的磁盘文件。失败不留部分实体。
  Human 和 MCP 均经 ProjectSession ExecuteAuthoring，复用事务预算、Runtime/恢复锁。
- `prefab` 是 AssetRegistry 类型；按需从磁盘读取 CPU 模板，无 GPU 资源或全局缓存。
  注册资产加载会校验非空外部资产引用的存在性和类型；跨项目模板须保留对应资产身份。
  保存导出生成新的 `Prefabs/<asset UUID>.prefab`，随后原子保存 registry，再发布内存
  registry。磁盘失败回收新文件；不覆盖旧资产，不改变 Scene dirty/history。
  两个文件之间不承诺跨文件崩溃事务，崩溃可能留下未注册文件；重开不加载该文件。
- 插入前拒绝重复 primary Camera、重复 Canvas 或非根 Canvas，保留现有场景配置。
- Export 在 Runtime、transaction、recovery 期间拒绝。Human 在 Hierarchy 导出，
  Asset Browser 实例化；MCP `scene.export_prefab` 分类 SceneSave（保存作者子树到
  项目资产），`scene.instantiate_prefab` 分类 SceneWrite。权限与主线程路由保持原样。
