# Janus v0.4 Asset + Serialization 详细设计

**状态：** Proposed  
**目标版本：** v0.4  
**前置版本：** v0.3 ECS + Scene  
**前置修复：** PR #7 `fix: harden ECS entity validation and transform propagation` 合并后开始实现  

---

## 1. 背景

Janus v0.1-v0.3 已完成从 Engine Foundation、Renderer2D 到 ECS + Scene 的首个 Runtime 闭环。当前 World 仍主要由 C++ 在启动时创建，Entity、Component 与 GPU Resource 都只存在于进程内存中。

v0.4 的任务不是简单增加文件加载器，而是完成一次核心模型升级：

> **将 Janus 从 Runtime-only 内存世界升级为具有稳定身份、稳定资源引用和可保存/恢复能力的 Persistent Project Runtime。**

该阶段是后续 Lua、Editor、Reflection、CommandBus、MCP 的共同数据基础。

---

## 2. 当前基线与问题

当前 Scene 已拥有：

- `ECS::Entity`：index + generation；
- `TransformComponent`；
- `HierarchyComponent`；
- `SpriteRendererComponent`；
- `CameraComponent`；
- Scene-driven rendering。

Renderer 已拥有：

- `TextureHandle`；
- `ShaderHandle`；
- `FramebufferHandle`；
- `Renderer2D::CreateTexture`；
- RenderDevice/OpenGL backend。

但存在一个必须在 v0.4 解决的语义断层：

```text
SpriteRendererComponent
    ↓
TextureHandle
    ↓
Runtime GPU resource
```

`TextureHandle` 是本次运行中 GPU Resource Table 的句柄，不能作为 Scene 的持久化引用。

例如：

```text
Run A: player.png -> TextureHandle{3}
Run B: player.png -> TextureHandle{7}
```

因此 Scene 文件不能保存 `TextureHandle`。

正确模型必须变为：

```text
Persistent World
    ↓
AssetHandle
    ↓
AssetRegistry
    ↓
AssetService / AssetCache
    ↓
TextureHandle
    ↓
Renderer
```

## 5. 核心设计原则

### 5.1 Runtime identity 与 Persistent identity 分离

```text
ECS::Entity
= Runtime identity
= index + generation

UUID
= Persistent identity
= cross-run stable
```

禁止把 ECS index/generation 写入 Scene 文件。

### 5.2 Asset identity 与 GPU resource identity 分离

```text
AssetHandle
= Persistent resource identity

TextureHandle
= Runtime GPU identity
```

禁止将 `TextureHandle`、`ShaderHandle`、`FramebufferHandle` 序列化。

### 5.3 Scene 只拥有 World Data

Scene 长期职责：

- Entity lifetime；
- hierarchy；
- world/authoring data；
- scene metadata。

Scene 不继续吸收：

- asset loading；
- GPU resource lifetime；
- serialization implementation；
- future scripting/physics/audio execution。

### 5.4 无全局 AssetManager 单例

使用显式依赖：

```text
Application
    ├── Renderer2D
    ├── AssetService
    └── Scene
```

所有 Service 生命周期由上层拥有。

### 5.5 显式错误模型

所有文件、解析、资源加载与反序列化失败必须使用 `Result<T>` / `Error` 返回，不通过异常作为主要控制流。

## 8. UUID

### 8.1 API

建议提供：

```cpp
class UUID
{
public:
    [[nodiscard]] static UUID Random();
    [[nodiscard]] static Result<UUID> Parse(std::string_view value);

    [[nodiscard]] std::string ToString() const;
    [[nodiscard]] bool IsValid() const noexcept;

    auto operator<=>(const UUID&) const = default;
};
```

### 8.2 要求

- 使用 128-bit UUID；
- string representation 使用标准 canonical form；
- 支持 hash；
- default value 表示 invalid/null UUID；
- parse invalid string 返回显式错误；
- UUID implementation 位于 Core，不依赖 Scene / Asset / Renderer。

### 8.3 原则

不要复用 ECS generation；不要使用本地文件路径作为 identity；不要使用运行时自增整数作为持久化 identity。

## 9. Entity Persistent Identity

新增基础组件：

```cpp
struct EntityIdentityComponent
{
    UUID id;
    std::string name;
};
```

`Scene::CreateEntity()` 应保证每个新 Entity 默认拥有：

```text
EntityIdentityComponent
TransformComponent
HierarchyComponent
```

建议提供：

```cpp
ECS::Entity CreateEntity(std::string name = "Entity");
ECS::Entity CreateEntityWithUUID(UUID id, std::string name);
```

第二个接口仅用于 deserialize/clone 等受控路径，并必须拒绝 Scene 内重复 UUID。

Scene 建议维护：

```text
UUID -> ECS::Entity
```

索引，以支持：

- Deserialize hierarchy resolution；
- future Editor selection persistence；
- future MCP entity lookup；
- future Scene clone / Play Mode。

该索引的维护职责属于 Scene，而不是 ECS::Registry。

## 10. AssetHandle / AssetMetadata

### 10.1 AssetHandle

建议：

```cpp
struct AssetHandle
{
    UUID id;

    [[nodiscard]] bool IsValid() const noexcept;
    auto operator<=>(const AssetHandle&) const = default;
};
```

`AssetHandle` 是 persistent identity，不是 Renderer handle。

### 10.2 AssetType

首期：

```cpp
enum class AssetType
{
    Unknown,
    Texture,
    ShaderSource,
    Scene
};
```

仅实现当前 v0.4 需要类型；Audio/Lua/Animation 后续增加。

### 10.3 AssetMetadata

```cpp
struct AssetMetadata
{
    AssetHandle handle;
    AssetType type = AssetType::Unknown;
    std::filesystem::path relativePath;
};
```

约束：

- `relativePath` 必须相对 Project Root；
- 不允许 absolute path；
- 路径规范化后不能逃逸 Project Root（例如 `../../outside.png`）；
- registry 中 handle 与 path 都唯一。

---

## 11. AssetRegistry

职责：

```text
Persistent Asset Identity Database
```

不负责：

- 读取 PNG；
- 创建 GPU texture；
- cache runtime resource。

API 草案：

```cpp
class AssetRegistry
{
public:
    [[nodiscard]] Result<AssetHandle> Register(
        AssetType type,
        const std::filesystem::path& relativePath);

    [[nodiscard]] Result<void> Register(
        const AssetMetadata& metadata);

    [[nodiscard]] const AssetMetadata* Find(AssetHandle handle) const;
    [[nodiscard]] const AssetMetadata* FindByPath(
        const std::filesystem::path& relativePath) const;

    [[nodiscard]] bool Contains(AssetHandle handle) const;

    [[nodiscard]] Result<void> Load(
        const std::filesystem::path& registryPath);

    [[nodiscard]] Result<void> Save(
        const std::filesystem::path& registryPath) const;
};
```

内部至少维护：

```text
AssetHandle -> AssetMetadata
normalized relative path -> AssetHandle
```

## 13. AssetService

`AssetService` 是 Runtime asset capability，不是 singleton。

### 13.1 生命周期

由 Application 或未来 ProjectRuntime 显式拥有：

```text
Application
    ↓
AssetService
```

### 13.2 API 草案

```cpp
class AssetService
{
public:
    [[nodiscard]] Result<TextureHandle> LoadTexture(AssetHandle handle);
    [[nodiscard]] Result<std::string_view> LoadShaderSource(AssetHandle handle);

    [[nodiscard]] bool IsLoaded(AssetHandle handle) const;
    void Unload(AssetHandle handle);
    void Clear();
};
```

### 13.3 依赖

`AssetService` 可以依赖：

- Core/FileSystem；
- AssetRegistry；
- Renderer public API。

Asset 基础数据类型不应依赖 OpenGL backend。

## 14. Asset Cache

首期 Cache 解决：

```text
same AssetHandle loaded N times
    ↓
only one runtime resource
```

示例：

```text
AssetHandle(texture-A)
      ↓
AssetCache
      ↓ cache hit
TextureHandle{5}
```

第一版可以使用：

```text
unordered_map<AssetHandle, TextureHandle>
unordered_map<AssetHandle, string>
```

不要求统一复杂 polymorphic Asset object hierarchy。

重点保持语义清楚：

```text
Persistent handle -> Runtime resource
```

资源销毁由 AssetService 负责调用 Renderer 对应 destroy API。

## 15. Texture Loader

建议引入 `stb_image`。

流程：

```text
AssetHandle
    ↓
AssetRegistry metadata
    ↓
ProjectRoot / relativePath
    ↓
FileSystem / stb_image
    ↓
RGBA8 pixel data
    ↓
TextureDesc
    ↓
Renderer2D::CreateTexture
    ↓
TextureHandle
    ↓
AssetCache
```

### 15.1 错误情况

必须覆盖：

- handle 未注册；
- AssetType != Texture；
- 文件不存在；
- 文件不可读；
- image decode 失败；
- invalid dimensions；
- renderer create texture 失败。

错误消息必须携带足够上下文：handle / relative path / cause。

## 16. Shader Source Loader

v0.4 只负责：

```text
AssetHandle
    ↓
Shader source text
```

不在本阶段增加 Material System 或 Scene custom shader。

目标是建立 Asset 类型扩展范式，而不是扩大 Renderer 范围。

## 17. SpriteRendererComponent 迁移

当前：

```cpp
struct SpriteRendererComponent
{
    TextureHandle texture;
    ...
};
```

v0.4 应迁移为：

```cpp
struct SpriteRendererComponent
{
    AssetHandle texture;
    Vector2 size{1.0f, 1.0f};
    Color color = Color::White();
    i32 layer = 0;
    TextureRegion uv = TextureRegion::Full();
    bool enabled = true;
};
```

原则：

> Component 保存 authoring/persistent state，不保存 GPU state。

运行时解析发生在 SceneRenderer/Render extraction 阶段。

---

## 18. Scene 与 SceneRenderer 分离

v0.3 当前由 `Scene::Render(Renderer2D&, Viewport)` 承担 transform update、camera selection 与 sprite submission。

v0.4 引入 AssetService 后，不建议继续扩展为：

```text
Scene::Render(Renderer2D&, AssetService&, Viewport)
```

建议引入：

```cpp
class SceneRenderer
{
public:
    [[nodiscard]] Result<void> Render(
        Scene& scene,
        AssetService& assets,
        Renderer2D& renderer,
        Viewport viewport);
};
```

职责：

- select runtime camera；
- update/consume world transforms；
- query renderable components；
- resolve `AssetHandle -> TextureHandle`；
- submit sprites。

Scene 本身保留：

- entity lifetime；
- hierarchy；
- identity；
- component access；
- scene metadata。

这为未来 Scene View / Game View / headless runtime 提供更清晰边界。

## 23. SceneSerializer

API 草案：

```cpp
class SceneSerializer
{
public:
    [[nodiscard]] static Result<std::string> Serialize(
        const Scene& scene);

    [[nodiscard]] static Result<void> Save(
        const Scene& scene,
        const std::filesystem::path& path);

    [[nodiscard]] static Result<std::unique_ptr<Scene>> Deserialize(
        std::string_view text);

    [[nodiscard]] static Result<std::unique_ptr<Scene>> Load(
        const std::filesystem::path& path);
};
```

v0.4 不依赖 Reflection，当前 Component 使用显式 serializer function：

```text
SerializeTransform
SerializeSpriteRenderer
SerializeCamera
```

未来 v0.7 可将内部实现替换为 Reflection metadata，但尽量保持 `.scene` schema 稳定。

## 24. Deserialize 两阶段算法

禁止单遍读取时直接建立 parent relation。

必须至少两阶段：

### Phase A：创建 World

```text
Parse JSON
    ↓
Validate schema/version
    ↓
Validate entity UUID uniqueness
    ↓
Create all entities with UUID
    ↓
UUID -> ECS::Entity map
    ↓
Deserialize components
```

### Phase B：Resolve references

```text
for each serialized entity
    ↓
resolve parent UUID
    ↓
Scene::SetParent
    ↓
validate cycles / missing references
```

这样不依赖 parent 在文件中先于 child 出现。

反序列化失败不得返回半初始化 Scene 给调用者。

---

## 25. Atomic File Write

当前普通 `WriteText/WriteBinary` 直接 truncate 目标文件。Scene、AssetRegistry、Project Config 需要更安全的持久化语义。

新增：

```cpp
Result<void> WriteTextAtomic(...);
Result<void> WriteBinaryAtomic(...);
```

概念流程：

```text
target.scene.tmp
    ↓ write complete
flush / close
    ↓
replace target.scene
```

要求：

- write 失败时原目标文件保持可用；
- temp file 清理失败只记录明确错误/警告；
- Windows replace/rename 语义需测试；
- 不在 v0.4 实现 journal/database。

---

## 26. JSON Dependency

建议使用 `nlohmann/json`。

原因：

- 成熟稳定；
- C++20 易集成；
- 不浪费项目价值在自研 parser；
- JSON 对 Git、Human、Agent 都友好。

CMake 使用固定版本 `FetchContent`。

## 29. 测试策略

### 29.1 UUID

- Random UUID valid；
- UUID uniqueness smoke test；
- ToString -> Parse round-trip；
- invalid input rejection；
- hash/equality。

### 29.2 AssetRegistry

- register and lookup by handle；
- lookup by path；
- duplicate handle rejection；
- duplicate normalized path rejection；
- absolute path rejection；
- project escape rejection；
- save/load round-trip；
- invalid schema/version rejection。

### 29.3 AssetService

- missing handle；
- wrong type；
- valid texture load；
- decode failure；
- duplicate load cache hit；
- unload destroys runtime resource；
- clear releases all resources。

优先使用 FakeRenderDevice/Test Access 验证创建次数，不要求单元测试依赖真实 OpenGL window。

### 29.4 Scene Serialization

- empty scene round-trip；
- entity UUID/name round-trip；
- transform round-trip；
- camera round-trip；
- sprite AssetHandle round-trip；
- parent/child hierarchy round-trip；
- three-level hierarchy；
- parent serialized after child；
- duplicate UUID rejection；
- missing parent rejection；
- invalid asset handle format rejection；
- unsupported schema version rejection。

### 29.5 Round-trip invariant

核心验收：

```text
Scene A
    ↓ Serialize
Text A
    ↓ Deserialize
Scene B
    ↓ Serialize
Text B
```

不要求 JSON whitespace 完全一致，但 authoring semantic state 必须等价。

## 30. Sandbox Vertical Slice

v0.4 完成时 Sandbox 不再以“代码手工创建 GPU checker texture”为主要资源工作流。

目标示例：

```text
SandboxProject/
├── Assets/
│   └── player.png
├── Scenes/
│   └── Battle.scene
└── Config/
    └── AssetRegistry.json
```

运行：

```text
Load AssetRegistry
    ↓
Load Battle.scene
    ↓
Scene reconstructed
    ↓
SpriteRenderer contains AssetHandle
    ↓
SceneRenderer resolves texture
    ↓
AssetService cache
    ↓
Renderer2D
```

这是 v0.4 最终产品闭环。

## 35. 关键架构决策总结

1. `ECS::Entity` 不承担持久化身份；UUID 承担。
2. `TextureHandle` 不承担 Asset 身份；`AssetHandle` 承担。
3. Component 保存 authoring state，不保存 GPU state。
4. AssetRegistry 只管理 metadata，不负责 loading/cache。
5. AssetService 负责 runtime resolve 与 resource lifetime。
6. Scene 不继续吸收 renderer/asset implementation；引入 SceneRenderer。
7. v0.4 手写 Component serialization，v0.7 再接 Reflection。
8. JSON schema 必须带 `schema` + `version`。
9. Scene deserialize 使用 create-all + resolve-references 两阶段算法。
10. Persistent files 使用 atomic write。
11. 所有 path 在 registry 中使用 project-relative normalized path。
12. v0.4 完成标准是磁盘项目 -> Scene -> Asset resolve -> Render 的纵向闭环，而不是 API 数量。

## 36. 最终定义

v0.4 完成后，Janus 应从：

> “可以在 C++ 中构造一个 2D ECS Scene 并渲染”

升级为：

> **“可以从稳定的项目数据和资源引用恢复一个 2D 世界，并安全地保存、重新加载和渲染它。”**

这是 Janus 后续成为 Editor-capable 与 Agent-native Engine 的数据基础。
