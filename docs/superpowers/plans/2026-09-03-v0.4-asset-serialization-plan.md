# Janus v0.4 Asset + Serialization Implementation Plan

> **For agentic workers:** 按 #9 → #10 → #11 → #12 顺序执行。每个任务严格遵守：先补失败测试 → 实现最小能力 → 跑窄测试 → 跑全量测试 → 检查 diff → 提交 PR。不要跨 Issue 预实现后续能力。

**Goal:** 将 Janus 从 Runtime-only ECS Scene 升级为可从持久化项目文件恢复 Scene 与 Asset 的 2D Engine Runtime，并建立后续 Lua、Editor、Reflection、MCP 共用的稳定 identity / persistence 基础。

**Architecture:** 引入 `UUID`、`AssetHandle`、`AssetRegistry`、`AssetService`、`AssetCache`、`SceneSerializer` 与 `SceneRenderer`。Scene/Component 保存 authoring/persistent state；GPU `TextureHandle` 只存在于 AssetService/Renderer runtime。Scene serialization 使用版本化 JSON，资源路径使用 project-relative path。

**Tech Stack:** C++20、CMake 3.24+、MSVC、SDL3、OpenGL 4.5、glad、glm、Catch2、nlohmann/json、stb_image。

**Spec:** `docs/superpowers/specs/2026-09-03-v0.4-asset-serialization-design.md`

**Tracking Issues:**

- #9 Persistent Identity + AssetRegistry
- #10 Asset Loading + Runtime Cache
- #11 Persistent Scene + SceneRenderer
- #12 Disk-backed Vertical Slice

---

## Global Constraints

- v0.4 不实现 Lua、Editor、Reflection、CommandBus、MCP、Prefab、Physics、Audio、Animation 或 UI。
- `Core` 不依赖 Asset、Scene、Renderer、SDL 或 OpenGL。
- `AssetHandle` 与 `TextureHandle` 必须保持不同语义和不同类型。
- `ECS::Entity` 仍是 runtime handle；持久化引用必须使用 UUID。
- Scene/Component 不保存 GPU resource handle。
- AssetRegistry 只负责 metadata，不负责 runtime loading/cache。
- AssetService 不得设计为 global singleton。
- Scene 不得新增 AssetService/Renderer 业务依赖；render extraction 进入 `SceneRenderer`。
- Persistent 文件必须带 `schema` + `version`。
- Asset path 必须 project-relative、normalized，并拒绝 project-root escape。
- 所有文件/解析/加载失败走 `Result<T>` / `Error`。
- 自动测试优先使用 fake RenderDevice，不依赖真实窗口和 GPU。
- 不为满足 roadmap checklist 而提前扩展 Material/custom shader 系统。
- 每个 PR 只完成当前 Issue 的 acceptance criteria；后续能力留给后续 PR。

# PR Rules

Each implementation issue maps to one primary PR:

```text
#9  -> feat: add persistent identity and asset registry
#10 -> feat: add asset loading service and cache
#11 -> feat: add scene persistence and scene renderer
#12 -> feat: complete v0.4 disk-backed project loop
```

PR description must include:

- Summary
- Architecture changes
- File responsibility changes
- Tests added
- Verification commands/results
- Explicit out-of-scope statement
- `Closes #<issue>`

Do not combine multiple phases into one giant PR unless a concrete dependency makes separation impossible.

# Completion Definition

v0.4 is complete only when the engine can demonstrate:

```text
Persistent Project Data
    ↓
AssetRegistry + Scene JSON
    ↓
Stable UUID / AssetHandle references
    ↓
Runtime Scene reconstruction
    ↓
AssetService runtime resolution/cache
    ↓
SceneRenderer
    ↓
Renderer2D
    ↓
Visible 2D output
```

and can safely serialize the authoring state back to disk without embedding runtime-only identifiers.
