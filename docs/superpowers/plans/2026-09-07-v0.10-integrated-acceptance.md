## 范围与决策

- Game 默认进入 Integrated 场景：现有 Combat.lua 继续独占卡牌规则，
  UI 菜单/卡牌、两个展开的 Fighter Prefab、动画、PCM 音效、物理落地与受击反馈共同运行。
  物理反馈不改变已经验证的伤害结算规则。
- Prefab 仍是编辑时展开；角色通过共享命令实例化，不增加运行时生成、实例关联或覆盖系统。
- 验证场景调用同一 Game 规则入口，允许 Agent 用中性 Step 复现胜负，
  不新增 MCP 输入注入。正常场景只响应人类输入。
- RuntimeExecution 接收可选、借用的 CpuProfiler，宿主保证其生命周期；
  阶段计时复用会话持有的 profiler，不使用全局对象。独立 Application 持有自己的 recorder。
  记录 UI、脚本重载、Lua、Physics、Animation、Audio；渲染单独记录 CPU 提交时间。
- 保留各系统的独立展示与旧验收场景。完整肉鸽、多场景、存档、Prefab overrides 留待后续。

## 验证顺序

1. 先添加集成胜负/重开、暂停/中性 Step、作者态隔离、宿主一致性和计时故障闭合测试。
2. 实现 Game 场景、模板与共享诊断；通过最窄测试。
3. MCP 两协议验证模板发现、事务回滚、实例配置、保存/重开、受保护运行、快照、日志。
4. 原生 Editor 和 Sandbox 检查实际渲染、输入及音频输出；记录观察与自动化证据的区别。
5. 记录固定工作量 CPU 与 Renderer 基线。16.67 ms 是 60 Hz 整帧预算，
   不把 Debug/FakeRenderDevice 时间当成 GPU 时间或发布性能保证。
6. 双预设配置/构建、完整 CTest、diff 检查，更新验证记录与路线图。
