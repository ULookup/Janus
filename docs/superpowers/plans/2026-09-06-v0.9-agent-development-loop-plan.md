## 1. 执行原则

本计划的 `09-01` 等编号为本地工作包 ID，不是 GitHub Issue 编号。本次在同一实施分支完成，并通过一个集成 PR 提交。下方保留原始执行计划，实际交付和验证以实施记录为准。

依赖主线：

```text
09-01 Design
  → 09-02 Runtime
  → 09-03 Logs
  → 09-04 Runtime MCP / Debug E2E      [Gate A]
  → 09-05 CPU Profiler
  → 09-06 Profiler Views / Resource   [Gate B]
  → 09-07 CommandGroup / Transactions
  → 09-08 Host / MCP Transactions     [Gate C]
  → 09-09 Audit / Agent Activity
  → 09-10 Final Validation           [Gate D: v0.9]
```

每个工作包先增加失败测试，再实现。保持代码可编译、现有能力可用；接口迁移和调用方在同一 PR 中完成。建议一包一 PR，若因文件规模拆分，子 PR 也必须可构建并有实际消费者。

不估算固定完成日期：先完成 09-02，依据实测工作量再排日历。风险主要集中于暂停/故障语义、分组补偿、跨请求事务和关闭清理，不以文件数量估工时。

## 2. 工作包

### 09-01 — 冻结设计和验收基线

建议标题：`docs(v0.9): define Agent Development Loop contracts`

- 落地配套设计，关联 PRD/路线图/架构中的范围和事务语义。
- 明确四态 Runtime、单帧 Step、暂停只读、故障现场保留。
- 明确事务 provisional 可见、共享历史、超时/断连回滚和 RecoveryRequired。
- 保留主协议与 legacy 兼容、stdout 规则和 GPU-free 测试策略。

出口：设计可以直接指导下一包的行为测试；路线图仍标为下一里程碑，不提前标完成。

### 09-02 — Engine RuntimeSession 与 Editor 控制

建议标题：`feat(runtime): add pause step and fault-preserving sessions`

主要文件：新增 `Engine/Runtime/RuntimeSession.*`、Runtime 类型；迁移 `Editor/RuntimeSession.*`；更新 ProjectSession、EditorApplication、EditorViewSource 和 Engine/Editor CMake。

先测：

- Stopped/Playing/Paused/Faulted 全部转换和非法操作；
- OnCreate/OnDestroy 次数，Pause/Resume 不重复 Clone；
- runtimeId、成功帧号、simulation time、启动失败清理；
- Step 固定 dt/空输入、长寿命输入引用、普通 Paused tick 不推进；
- fault 保留 Scene，Stop 错误仍清理；
- Paused/Faulted 不允许作者态 Execute/Undo/Redo/Save。

实现：提供 typed status/read 能力；UI 加 Pause/Resume/Step；替换“Update 错误立即 Stop”路径。保留 ManagedRuntime/Sandbox 行为，不借迁移加入 Scheduler。

出口：Human 可完成 Play → Pause → Step → Resume → Stop；FakeRenderDevice 集成验证编辑态不受污染。

### 09-03 — 统一结构化日志

建议标题：`feat(diagnostics): share bounded structured logs across hosts`

主要文件：Core/Log 存储与 sink、Application diagnostics 生命周期、Runtime/Scripting 错误入口、EditorConsole/ConsolePanel。

先测：容量、截断、sequence/gap、筛选游标、并发写读、RAII detach、同一错误不重复记录、初始化前/销毁后安全、MCP 模式 stdout 无日志。

实现：沿用 spdlog，增加可注入 LogStore；旧 Console 包装写入统一存储；新增 Runtime/Lua 上下文。

出口：Editor Console 能显示同源 Engine/Runtime 错误，核心查询不依赖 UI 或 JSON。

### 09-04 — Runtime/Logs MCP 和最小 Debug 闭环

建议标题：`feat(mcp): expose runtime control state and diagnostic logs`

主要文件：MCP RuntimeTools/RuntimeResources/LogResources、权限分类、McpEditorHost、Tests/MCP/McpExternalHost.cpp 和 Python E2E。

先测：

- 四个 runtime tools 的参数、结果、实际执行时机和线程；
- runtime resource 读取真实运行态、无副作用、Stop 后无悬空引用；
- 作者态资源语义保持兼容；
- 日志有界查询，未知操作不能降级为 Read 权限；
- modern/legacy 同一能力链。

实现：host 注入 typed callbacks；测试宿主调用生产 Runtime tick，使用独立临时脚本和测试时钟；不复制 handlers。

**Gate A：** Agent 修改 → startPaused → Step × 3 → 读 Transform/日志 → Stop；故障脚本可观察并重新启动验证。Gate A 通过后才进入 Profiler，不把所有诊断能力等到最后一起集成。

### 09-05 — CPU Profiler 基础

建议标题：`feat(profiling): record bounded CPU frame scopes`

主要文件：Engine/Core/Profiling、Diagnostics snapshot、Profiler unit tests；必要的 Application/Runtime instrumentation。

先测：注入时钟、RAII 提前返回、父子 scope、线程归属、跨 frame 完成、启停采样、容量截断、历史淘汰、未完成 frame 不发布。

实现：显式 recorder/context；CPU 与 wall 时间口径分离；无新全局 singleton，无 GPU profiler。

出口：无 Editor 的 Engine 测试可产生和查询完成的 CPU profile；已有 Runtime 消费该 recorder。

### 09-06 — Renderer 统计、Profiler 面板和 MCP

建议标题：`feat(profiling): share render pass and CPU profiles with agents`

主要文件：EditorApplication render pass capture、ProfilerPanel、MCP ProfilerResources、Engine Diagnostics 合成。

先测：Scene/Game pass reset 隔离、隐藏视图 unavailable、实体数与提交 Sprite 数区分、frameId 淘汰、Editor/MCP 同一 snapshot。

实现：每个 pass 结束复制 RendererStatistics，资源只读最后完成帧；面板显示 CPU 分解及两视图计数。

**Gate B：** 一次可重复 workload 同时在 Editor 和 MCP 得到一致计数；记录采样开/关性能基线和环境。Fake renderer 不提供 GPU 性能结论。

### 09-07 — CommandGroup、事务核心与 receipts

建议标题：`feat(command): add bounded reversible transaction groups`

主要文件：Core/Command、Scene commands 的 receipt/effect 与 snapshot budget 支持；Core/Scene command tests。

先测：

- pending group 不增加 history、不丢 redo tail；
- Commit 接管已执行命令，不二次执行；空组无历史；
- 逆序 Rollback，Create→Add→Set 依赖；
- Undo/Redo 部分失败时的对称补偿和 cursor；
- observer 不重入，成功/失败/Pending receipts；
- 命令数/快照预算、未知 command 拒绝加入；
- rollback 补偿失败保留 RecoveryRequired 和错误位置。

实现：核心事务状态不认识 JSON/Editor/Runtime；Scene 内置命令维持 UUID/snapshot 与 Camera.primary delta 不变量。

出口：Engine 测试验证一组命令 Commit 后只需一次 Undo/Redo；普通 v0.7 命令行为全部保留。

### 09-08 — 作者态协调与 MCP Transaction

建议标题：`feat(mcp): coordinate authoring transactions and disconnect rollback`

主要文件：ProjectSession 统一作者态入口、EditorActions、SceneTools context、TransactionTools/Resource、McpEditorHost lifecycle、Human 取消/恢复 UI。

先测：

- owner/token、Human 与 Agent 写冲突；
- Paused/Faulted/Playing 禁止 Begin，活跃事务禁止 Save/Play/Undo；
- dirty/history/redo tail 完整恢复，provisional resource 标识；
- fake clock 超时、EOF、worker 错误、Editor shutdown 无死锁；
- terminal 重试不重复 Commit/Rollback；
- 权限撤回不能绕过执行，也不能阻止 host cleanup；
- RecoveryRequired 禁止 Save/继续写；Human 恢复磁盘场景须明确放弃未保存状态。

**Gate C：** 外部 stdio 事务成功提交/中途失败/断连均有确定结果；一次 Human Undo 撤销整个 Agent 修改组。禁止使用手动 UI 禁用代替真实 guard。

### 09-09 — Audit 与 Agent Activity

建议标题：`feat(diagnostics): expose correlated agent activity and undo events`

主要文件：Engine Diagnostics ActivityStore、命令事件接收、host 无命令操作记录、ActivityResource、AgentActivityPanel。

先测：来源和 ID、Pending→Commit/Rollback、Human Undo/Redo 关联、权限拒绝、Runtime Control/Save 失败、摘要截断、游标 gap、查询不产生日志循环、诊断失败不改变业务结果。

实现：订阅 Engine receipt/effects，不在 UI/协议层复制业务 diff；不存完整源码或删除快照。

出口：用户和 Agent 都能知道谁改了什么、是否提交、是否回滚，以及后来是否被 Human Undo；不承诺持久或防篡改审计。

### 09-10 — 收尾与真实验证

建议标题：`test(v0.9): validate the complete Agent Development Loop`

- 合并 Runtime、Logs、Profiler、Transaction、Audit 的现代/legacy 子进程 E2E；
- 保留已有所有测试，补足关闭、限额、故障和反复启动压力场景；
- 在真实 Editor 验证可见控制、错误现场、面板和 Agent→Human Undo；记录真实 MCP client 配置与版本；
- 提交可复现的 Profiler 开关对比基线、采样配置、机器/构建条件；
- 同步 README、路线图、AGENTS 和本设计；统一生产版本标识方案，避免 CMake 与 server version 各自漂移；
- Git Tag/Release 属于后续发布动作，本计划不自动创建。

**Gate D：** 全部版本范围完成，完整验证零失败，明确已知限制，才把 v0.9 标记完成。

## 3. 每个行为 PR 的验证命令

在 Visual Studio Developer PowerShell 中，先运行该包新增的最窄测试，再完整回归：

```powershell
cmake --preset windows-msvc-debug
cmake --build --preset windows-msvc-debug
cmake --preset windows-msvc-debug-tests
cmake --build --preset windows-msvc-debug-tests
ctest --preset windows-msvc-debug-tests
git diff --check
```

本地内存不足时可给 build 增加 `--parallel 2`，不能删测试或降低 warnings 来换取通过。窄测试使用新增的 Catch2 tags/CTest 名称，确认匹配数大于零。

日志与临时产物放 ignored `out/`，测试 fixture 使用独立临时目录。读完验证结果后再报告完成；环境失败与代码回归必须区分。

## 4. 首轮执行建议

先落地 09-01，再实施 09-02。09-02 的第一个测试应证明：**Paused/Faulted 有 Runtime，但不能作者态写入，也不能继续普通 tick。** 这是后续 MCP 控制、运行态查询和事务互斥的共同前提。

不要先实现 Profiler UI、Audit 面板或全部 MCP schema。每个 schema 都应在对应 Engine 能力可测试之后接入。
